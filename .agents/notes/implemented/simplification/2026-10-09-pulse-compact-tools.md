# Agent Note: Pulse 紧凑工具与奖项展示

Status: implemented

## Problem

用户要求抽奖页集中展示奖项与操作，移除档位名称、卡片序号、重复券数、完成计数和光效选择，并将规则、权益信息和奖励记录收成小入口。

## Decision

复用现有问号展示用户指定的三段抽取规则。固定翡翠基础光效，不再读取旧配色偏好；奖励颜色仍按金额档位表现。卡片只保留图标、数量和单位。券数只显示一次，进行中和失败提示保留。

右上角小字按钮打开原生 dialog：我的权益展示等级、贡献和原额度期限；奖励记录展示原金额、状态、时间与编号。关闭与 Escape 使用原生焦点管理。权益刷新只替换弹窗内数据，不重建弹窗，历史轮询只更新记录，避免关闭弹窗或抢走焦点。演出模块失败时仍保留记录入口、规则和基础抽奖操作。

## Existing capabilities and note review

- [紧凑历史](../../implemented/simplification/2026-10-09-pulse-compact-history.md)：部分取代页面底部 details 与介绍内容的选择；社区其他紧凑页面、私人数据边界继续有效。
- [结果恢复](../../implemented/bug-fix/2026-10-09-pulse-result-recovery.md)：部分重叠，继续保留历史查询与抽奖按钮解耦、未确认原请求恢复；展示容器变为弹窗。
- 当前规则、50% 预设笔记：无经济决策冲突，不改 API、权限、概率、期限、券或预算。

## Alternatives considered

- 头部 details 浮层：更接近既有组件，但长历史表需要自行处理裁切、滚动和焦点边界；原生 dialog 提供顶层显示、Escape 和焦点恢复。
- 独立记录页：方便链接，但增加路由和身份加载维护；现有历史数据已可复用，使用同页弹窗。
- 保留底部折叠入口：改动少，但用户明确要求移动到上方，同时权益卡片仍占据首屏。

## Verification

正式前端回归、博客/社区构建与笔记检查通过。本地正式壳使用合成奖励验证桌面浅色中文、390px 深色中文和 320px 深色英文：五档卡片无辅助标签，问号只包含三段规则，弹窗通过 Enter 打开、Escape/关闭按钮返回入口焦点，长表仅在弹窗内滚动。抽奖后的资格刷新保留已打开的权益弹窗与关闭按钮焦点；到账更新保留记录弹窗，待到账继续单抽/五连抽，历史 503 保留旧记录并不锁按钮。持续 Action 503 保留原操作，恢复后继续原五次；演出脚本不可用时验证基础操作与权益弹窗。截图为 `output/playwright/pulse-compact-tools-desktop.png` 和 `pulse-compact-tools-mobile.png`，不代表生产普通账号验收。

## Consequences

弹窗打开时暂时限制页面其他交互，用户关闭后继续抽奖；关闭不等待发放。只调整展示位置，不减少历史接口读取，不新增私人数据缓存。
