# Agent Note: 徽章提示关闭后不重复弹出

Status: implemented

## Problem

生产帖子页可复现「好问题」徽章提示关闭后重现。Answer 1.7.1 的关闭依赖已读请求和 SWR 更新，三秒轮询可以重新展示旧缓存；服务端未用通知数据库验证缓存中的已读、归属和正常状态。尚未取得生产网络记录，不能断言具体是哪一种缓存异常。

## Decision

复用原生 BadgeModal、通知 API 和构建补丁。按账号记住用户已关闭徽章提示（跨页面范围由[后续导航修复](2026-11-15-badge-navigation-dismiss.md)接管），立即隐藏并停止动画，异步确认已读；无论同一旧通知或下一条排队徽章均不再次打断阅读；其他新徽章仍保留成就中心入口。服务端返回缓存徽章前验证通知数据库，过滤已读、失效和异属通知，不改变徽章授予或奖励规则。

活跃笔记检索 badge/notification/徽章：聊天通知与帖子作者等级均无关，没有现有归属笔记。

## Alternatives considered

- 只隐藏 DOM：上线快，但 React 和轮询会重建，且无法停止动画与恢复状态。
- 只修服务端：可消除已读缓存重放，但网络失败仍阻止关闭。
- 永久屏蔽所有徽章弹窗：容易实现，但会吞掉后续新徽章；仅当前 Layout 内按账号停止自动弹窗，重新加载页面恢复。

## Verification

关闭立即隐藏，失败和旧轮询不重开，同账号排队通知不连续弹出，其他账号正常；已读、删除和异属通知不能由缓存复活，数据库故障不误清缓存。固定上游补丁无模糊应用，Go race 回归、通知服务与控制器构建、实际 TSX 经 TypeScript 转译的 React 渲染回归通过；完整 forum 镜像和发布由 CI 继续验证，生产升级另行验收。

## Consequences

原 Layout 内存去重无法覆盖整页导航；[后续导航修复](2026-11-15-badge-navigation-dismiss.md)增加会话存储与后台禁用规则。状态轮询新增数据库核验，缓存为空时无额外查询。
