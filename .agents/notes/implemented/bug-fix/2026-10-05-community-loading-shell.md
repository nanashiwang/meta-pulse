# Agent Note: 社区完整首屏骨架与历史恢复

Status: implemented

## Problem

从 Answer 帖子后退到 `/latest`，未命中浏览器整页恢复时，先显示只有“最新讨论”标题和说明的 SEO 占位，再加载界面和帖子。线上捕获过 432ms 出现占位、889ms 显示列表；这是该次浏览器请求的证据，不是性能承诺。其他公开 SEO 页同样缺少导航，通用 shell 的 app 甚至为空。已命中 bfcache 的页面又会被 pageshow/popstate 清成加载占位。

## Decision

在现有 Python 静态构建中输出包含页头、侧栏、主内容和手机导航的匿名骨架。共用一个内容骨架模板，供构建首屏和运行时路由加载使用；区分紧凑话题流、一般列表、卡片网格与一般面板。社区自有页面按用户要求去掉外层装饰标题与提示横条，从筛选、内容或操作区开始；标签上下文放在筛选栏的小标签中。所有布局的骨架同步收紧，网格及面板不显示多余工具栏占位；保留不可见的页面标题与加载状态。该展示范围由[紧凑页面笔记](../simplification/2026-10-09-pulse-compact-history.md)维护。公开 SEO 文案保留在无脚本回退中，真实帖子仍由 Answer 提供。轻量加载模块处理语言偏好和脚本失败提示。

历史恢复只保留已完成、相同 URL/语言/会话的公开内容 DOM，后台更新；失败显示可见重试提示。筛选/分页变化和私人、管理、权益页面继续加载及实时身份校验，不持久缓存 HTML、身份、余额或 Token。更新时不抢焦点、不强制滚动到页首，旧请求仍受导航序号约束。

## Existing capabilities and note review

复用 `build.py`、`seo.py`、app 的导航与页面渲染、已有 CSS 和公开数据短缓存。影响 `/`、`/latest`、`/topics`、`/topic/*`、`/search`、知识库/帮助/规范及通用 shell 入口。Answer 原生页和博客继续使用各自页面。检索活跃笔记的 navigation/skeleton/首屏/缓存/返回/SEO，无现有 owner；已有脉冲演出和基础设施笔记不重叠。

## Alternatives considered

- 只调整 app.js 的加载动画：改动最小，但脚本执行前仍是空白或简化 SEO 页，不能解决用户指出的阶段。
- 将详情迁入 METAR 或引入完整服务端渲染：可统一页面生命周期，但需要迁移 Answer 的编辑器和权限行为，远超本次问题。
- 在 Node 中运行共享前端组件来生成首屏：减少导航标记重复，但现有服务器的社区构建仅要求 Python；为骨架新增服务器工具依赖不合适。采用静态匿名 chrome 和共用内容模板，使用既有布局 CSS，并验收两阶段一致性。

## Consequences

所有构建 HTML 在 app.js 执行前都有完整骨架与公开导航；主脚本失败或加载超时，内容上方显示恢复入口。公开页恢复时保持可读，私人入口仍重新验证。骨架不包含伪造身份或业务数据，不新增数据持久化。

匿名 chrome 与运行时 chrome 的标记有维护成本，使用相同 CSS 并覆盖导航链接/布局回归。骨架只能缩小视觉空档，不能代表接口更快。保留公开内容时必须明确后台更新失败，禁止把旧数据暗示为最新。如果未来迁移到共享渲染组件或改动导航结构，应同步检查两阶段结构，不继续扩展成第二套业务视图。
