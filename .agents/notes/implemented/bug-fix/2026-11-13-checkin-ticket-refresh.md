# Agent Note: 签到赠券自动刷新

Status: implemented

## Problem

用户观察到签到后需刷新浏览器才能看到券数，且社区成长与抽奖页入口重复。本地起始版本尚未查询交付结果；同步远程后已有自动刷新与独立签到交付标志，但仍需统一入口，并补齐丢响应恢复、手动进度刷新及部分到账更新。

## Decision

复用现有签到、tasks 和 refreshPulse 接口，在签到后有界查询任务进度，到账后刷新权威抽奖资格和券数。沿用远程 checkin_delivered 独立签到交付标志，不能用其他任务已到账推断签到到账；旧服务器缺字段时每三轮刷新权益并保留等待状态。保留本次已确认签到状态，避免采集延迟重新启用按钮。刷新失败可重试，离开页面或切换身份后丢弃旧响应。保留手动刷新入口。按用户确认移除成长页和个人空间的签到按钮，统一到 `/pulse`；未绑定用户在同一入口直接使用 Answer EXP 签到与状态接口，保留独立签到资格，不调用 Pulse/BFF。

## Existing decisions

[社区赠券](../../implemented/feature/2026-11-06-community-tickets.md)部分重叠，继续拥有异步采集、绑定、日上限及账本事实源，本篇只拥有浏览器刷新行为。[券统计与签到同步](2026-11-13-ticket-statistics-and-checkin.md)部分重叠，继续拥有独立签到交付标志和刷新成功语义；本篇调整入口、等待调度和恢复。检索命中的消费退役、运营统计、人工赠券与导航笔记不拥有本次刷新流程。

## Alternatives considered

- 点击即增加显示券数：响应最快，但还未到账或未满足资格时会虚增；采用服务端资格结果。
- 签到请求同步发券：无需浏览器等待，但会让经验签到依赖 Pulse 的可用性，改变现有后台交付边界。
- 保留手动刷新：代码最少，但签到和抽奖的连续操作被打断。

## Verification

`node --test metar-frontend/production/tests/pulse-checkin.test.js` 的 11 项回归覆盖延迟采集、部分/完整到账、失败重试、重复点击、身份/路由切换、重试上限、手动恢复、未绑定经验签到和成长卡按钮移除。`make test-community` 与 `make build-community` 通过。日上限、幂等和资金接口不变。测试使用模拟服务与时钟，不代替生产后台真实交付验收。

## Consequences

每 5 秒只读重试、最多 12 次，增加有限的任务查询成本；部分到账即可更新可用券，不等待其他任务全部交付。后台故障超过窗口会提示手动继续查询，不能承诺立即发券。任务与成长信息入口分离，未绑定用户的经验签到资格保持不变。机器人仍可模拟已登录用户；本次刷新修复不等于人机校验。
