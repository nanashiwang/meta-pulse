# Agent Note: 帖子列表显示发布者

Status: implemented

## Problem

最近活跃列表的 operator 是最近编辑/回答者，前端在 user_info 缺失时用其作为作者，导致头像、昵称、个人链接和等级显示成他人。

## Decision

扩展 Answer 的 QuestionPageResp，独立添加公开 user_info，作者 ID 仅用于服务端装配且不序列化。FormatQuestionsPage 复用已有作者 ID 批量用户查询，无新增逐帖请求。operator 原语义与排序不变，前端仅在缺少 user_info 且 operation_type 明确为 asked 时，使用原始发布事件的 operator 兼容旧接口；modified/answered 等活动者绝不作为作者。个人帖子和收藏的既有 user_info 保留使用。此决定扩展社区导航集成的列表身份显示，不改变 Answer 身份事实源。

列表同时返回可选 `last_reply: { user_info, created_at }`，复用列表原有的最后回答读取与用户批量查询；只公开 available 状态的回答，身份取回答的 UserID 而非 LastEditUserID。内部 UserID 不序列化。不额外逐帖请求或改变 operator/排序语义。前端不以 operator 推断最后回复：零回答显示邀请，有回答但缺少 last_reply 时显示「已有回答」，避免混合版本和已删除/待审回答产生错误归属。

列表采用左侧作者头像、标题与最多 28 个 Unicode 字符的纯文本摘要、底部作者/发布时间/标签、右上回答数、右下最后回复的布局。桌面底部共用网格行；手机宽度不足时回复信息另起一行。复用首页、分类、个人帖子和收藏的 questionRow，不重建排序、分类或导航系统。

## Alternatives considered

- 前端逐帖读取详情：可获得作者，但每页新增大量请求，放大当前延迟。
- 覆盖 operator 为发布者：改动少，但破坏 Answer 原生最近活动语义。
- 将 operator 当作最后回复者：newest 列表与编辑后记录含义不符，且回答编辑者不是回答发布者。
- 为布局另建首页与内容模型：重复现有筛选和内容能力，扩大路由与部署风险。

## Verification

前端 229 项测试通过，覆盖发布者与回复者分离、缺少回复字段、零回答、摘要 Unicode 截断及现有筛选/双语回归。正式静态构建通过；叠加现有补丁后 Answer schema 测试与 question_common 编译通过。真实样式在桌面与 375px 窄屏进行浏览器检查，桌面发布者与最后回复中心线一致，标题/摘要间距 1px，长用户名截断，窄屏无横向溢出。Windows 无法执行依赖 POSIX preexec_fn 的 umask 用例，仍须 Linux CI 验证。

## Consequences

需同时部署 forum 与社区静态资源。旧服务未返回 user_info 时，asked 记录仍显示正确发布者；其他活动记录显示未知作者而不冒用活动者；后端不增加敏感用户字段或独立查询。

## Production layout regression (2026-11-13)

正式等级脚本把头像占位字母视为用户名，在独立头像链接中重复注入等级，使跨两行头像高度达到约 69px，并将帖子行撑至约 114px。仅验证静态样式未覆盖此生产集成行为。头像链接改为固定尺寸并跨三行；等级脚本对头像和最后回复链接仅保留外观处理、不附加等级，CSS 同时隐藏旧缓存脚本添加的徽章。相同用户的头像/名字共享未完成资料请求时，两处都等待结果，不能因缓存尚无 value 跳过名字。

用线上真实列表和完整脚本、替换本地修复资源验证：桌面帖子行约 85px，标题摘要间距 1px，头像无徽章、名字保留一次等级；375px 无水平溢出。3 项脚本回归覆盖头像占位字母、照片、旧徽章、回复链接和共享未完成请求。首次排查时线上有回答记录尚无 last_reply；本次结束前复查已返回该字段。CSS 修复不能代替后端部署。

## Discussion sidebar

右侧复用 Answer 公开列表：等你来回答读取 order=unanswered、最多五条并过滤非零回答；精选阅读读取既有 feeds（好文收藏）标签、order=score、最多五条，隐藏查看全部入口，列表项之间使用细分隔线与留白。Answer recommend 实际是关注推荐，不能作为人工精选。沿用现有内容缓存与权限，不新增榜单表或逐帖详情查询。

两个区块在 renderView 插入 DOM 后并行挂载，不等待侧栏才显示主列表；独立失败和空状态，页面序号、节点连接与身份作用域校验防止迟到结果覆盖其他页面。沿用已关注标签卡片，窄屏放在主列表后。相比直接写死预览标题，此方案保持真实内容；相比随热门内容自动冒充精选，明确限定现有收藏栏目，但该栏目仍由既有标签权限管理，并非新增管理员精选机制。

验证：307 项前端/插件回归通过，正式构建通过；侧栏测试覆盖数据来源、转义、空态、独立失败、切页竞态、条数及挂载时机。以完整本地构建资源加线上公开数据浏览器验证，两块各五条，页面无脚本错误，375px 无横向溢出。
