# Agent Note: 历史券展示校正与签到同步

Status: implemented

## Problem

用户要求清理历史异常发券带来的巨大累计/移除统计，同时确认签到后自动刷新仍有提前退出问题。原统计读取 pulse_ledger_entry；不能为展示数字改写账本。

## Decision

新增 00021 迁移一次性记录已有用户的统计偏移与原始快照。校正后累计起点为历史已消耗券，移除起点为零，之后汇总减偏移正常增加；余额、券批次、奖励不变。基线采用 INSERT IGNORE，重试/回滚不覆盖审计记录。现行累计不是余额恒等式的组成项。

任务进度接口单独返回 checkin_delivered，仅检查今日 checkin 类别的交付确认。前端不再以全部任务累计相等推断签到完成，refreshPulse 实际更新成功才返回 true，遇忙继续检查；旧服务缺字段时每三轮刷新兼容。统一签到入口与后续轮询恢复由[签到刷新](2026-11-13-checkin-ticket-refresh.md)维护。

## Alternatives considered

- 删除或修改历史券流水：会破坏对账及历史奖励关联，因此只改统计投影。
- 始终隐藏移除并以消费替代累计：未来新增发券也无法正确统计，选择固定基线而非永久公式替代。
- 固定等待 100ms：不能覆盖异步赠券的 15 秒周期及失败重试。

## Verification

服务端迁移发现、MySQL 存储包及任务包编译和非数据库测试通过；新增数据库回归覆盖校正起点及后续发券/消费/过期、其他任务已交付但签到待交付。无专用 MySQL 测试连接，数据库回归在本机跳过，生产数据尚未执行迁移。签到前端回归通过，含刷新遇忙和既有任务券干扰。

## Consequences

需要配套部署 Pulse 迁移及 API、forum 与社区静态前端。迁移针对当时全体现有券用户，不是只修一个用户；原始历史可在基线表和账本审计。不保证即时到账，界面只展示服务端确认数据。
