# Agent Note: 跳过蓄能保留奖励揭晓

Status: implemented

## Problem

`pulse-core.js` 的复选框、系统减少动态效果、页面隐藏和无 Canvas 降级共用时间线的直接完成分支。用户勾选“跳过动画”后收到真实奖励便跳到终帧，整卡光幕、外放光晕和翻牌全部消失。用户要求只省略微光汇聚与蓄能，保留后半段演出。

## Decision

复用 `Timeline`、`cardFrame` 和 `View`，分离“跳过蓄能”与“立即展示结果”。复选框沿用本地偏好键，文案改为“跳过蓄能”，收到已确认结果后从原时间线 46% 处连续播放约 2.1 秒，保留全部卡片揭晓阶段。中途勾选只允许前进，已开始揭晓时不得重播或延后；取消勾选仅影响下一次开启。

系统减少动态效果、页面隐藏和无 Canvas 继续直接展示已确认结果。慢响应仍等待服务端结果并保持轻量呼吸；不新增请求、不修改随机或结算流程。

## Existing capabilities and note review

现有正式页面 `/pulse` 已有单抽、五连抽、持久偏好和五档 `cardFrame`；应扩展现有时间线，无需独立播放器。检索活跃笔记中的 skip、动画、脉冲、motion，未找到同一行为的归属笔记；现有能力审计流程笔记与本次运行时决定无重叠。入口、文案、时间线测试及架构/社区说明一起更新。

## Alternatives considered

- 保留整段跳过，仅说明开关含义：实现最简单，也适合只看结果，但不符合用户希望省去蓄能而保留闪光和翻牌的明确要求。
- 整段倍速播放：可以复用原始起点，但仍展示不需要的汇聚过程，并压缩用户希望保留的卡片演出。
- 从既有裂变/揭晓起点播放：保留原有卡片时序与五连抽错峰，只需要管理播放起点；采用此方案，并把无动画降级独立处理。

## Consequences

已有复选框偏好采用短演出语义，使用“跳过蓄能”及“保留闪光与翻牌”文案说明。相比原来的立即结束，多保留约 2.1 秒的奖励演出；完整时间线不变。增加短演出锚点的维护成本，由快/慢响应、先后顺序、五卡闪光和重复勾选回归约束。系统低动态优先于复选框，页面隐藏与无 Canvas 仍直接显示已确认结果。

## Verification

- 时间线回归验证完整 3.9 秒、短演出 2106ms、慢响应等待、五张卡的完整闪光、中途勾选、揭晓期间重复勾选与低动态优先级。
- `make test-community` 和 `make build-community` 通过；笔记树、格式及归档检查通过。
- Playwright 在与线上相同的 CSP 下验证已保存偏好、光幕先于奖励内容、单抽/五连抽、慢响应、动态切换低动态及页面隐藏、320px/390px 中英文与深色、无 Canvas。未发出真实业务抽奖。
- 本地模拟测得单抽短演出约 2154ms、五连抽约 2257ms，包含请求和浏览器操作开销；慢响应 2500ms 后仍保留揭晓，总计约 4652ms。低动态约 64ms、无 Canvas 五连抽约 171ms。该测量不代表生产设备性能。
- 既有浏览器回归通过第三次丢响应、刷新查询与原请求续跑、部分拒绝、离页暂停、到账状态更新和券不足场景。
