# Agent Note: 讨论列表加载完成后切换

Status: implemented

## Problem

最新、热门和类别筛选点击后，现有 navigate 会先将整个内容区替换为骨架；数据返回后才恢复列表，产生明显内容消失。Linux.do 的浏览器参考可观察到点击热门后旧列表仍存在，随后热门列表替换。

## Decision

将现有公开 DOM 保留机制扩展到同语言、同会话的讨论列表族：`/`、`/latest`、`/topic/:slug` 的排序、分页及类别/标签切换。URL继续表示用户请求的目标，列表、筛选高亮和页面元信息保留已提交版本，响应完成后在同一次渲染中更新。短请求不展示额外提示，超过 180ms 才提示加载新列表；失败保留旧列表并明确提供重试。401/403、身份或语言变化、私人及其他页面不复用。最新导航序号决定可提交结果；滚动在新列表成功提交后处理。

复用当前作用域的公开目录投影，避免列表提交时筛选控件短暂退回占位；仍后台刷新目录，不添加持久化页面、权限或金融数据缓存。

## Existing-note audit

[首屏与历史恢复](../../implemented/bug-fix/2026-10-05-community-loading-shell.md)继续约束首次加载和同 URL 恢复。本篇替代其中“筛选/分页变化先清空”的展示选择，保留私人页面、身份、语言和旧响应隔离规则。类别导航与侧栏布局不改动数据来源。

## Alternatives considered

- 增加淡入淡出：能修饰视觉，却仍会在网络请求期间移除可读内容。
- 立即把高亮改成目标筛选而保留旧列表：反馈快，但会在加载或失败期间把旧数据误标成新筛选。高亮与列表一起提交，延迟提示表达等待。
- 等数据返回后才改变 URL：可完全延迟地址切换，但需要重做现有 History/返回管理。本次保留请求 URL，以明确等待/失败状态和已提交内容高亮区分两者。

## Verification

生产壳浏览器夹具使用约 1.2 秒列表延迟，验证请求期间 DOM、工具栏与滚动不清空，提交时才改变列表/高亮；MutationObserver 在公开列表切换阶段未观察到列表缺失。乱序响应只保留最后目标；失败保留并重试；类别、分页与历史滚动、390px 英文深色通过。自动回归覆盖有效空列表、权限拒绝、身份/语言边界、私人页面跳转及旧响应隔离。首次站点访问仍显示原有骨架。

## Consequences

失败时 URL 表示请求目标而内容仍为原列表，必须显示明确提示。范围仅限公开讨论列表族，不扩大到草稿、聊天、权益或管理页面。
