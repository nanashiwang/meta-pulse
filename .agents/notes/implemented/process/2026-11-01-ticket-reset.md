# Agent Note: 全量可用券清零与 11 月 9 日重新起算

Status: implemented

## Problem

用户授权清零所有当前未使用脉冲券，并确认 2026-11-09 00:00 Asia/Shanghai 重新累计。生产 v0.2.69 同时存在历史定期账户和持续规则账户；持续规则跨快照保留贡献余数，券批次与账本均不可删除。

## Decision

持有项目发布锁 `.git/meta-pulse-update.lock`，复用现有 CursorSeekService、PeriodCreateService、AdminAdjustmentService，以同一个 UnitOfWork 事务执行一次运营操作。先锁采集游标和抽奖/规则创建公共锁，创建沿用原倍率、门槛、有效期和奖项的新持续快照，有限预算仅带入旧预算的可用部分；旧奖励仍归原预算。将所有正券余额追加负向调整至零，将持续规则的未成券余数追加贡献调整至零。游标定位到 2026-11-09 00:00 之前最后一秒的最大 ID，Worker 保持运行，到点自然读取新事件。

旧券批次及消费分配作为发行历史保留，旧来源账户为零，后续事件只归新的快照，不能使旧批次重新可用。旧 Usage、已中奖 Grant、结算与历史累计保留；不能将这次操作理解为清除财务历史。运营程序只组装既有服务，保存在受限操作证据目录，不部署应用、迁移 schema 或停止服务。

## Note review

[当前奖项规则](../../implemented/feature/2026-10-09-pulse-current-reward-rule.md)部分重叠：沿用快照、来源账户及当前规则选择，本次只记录一次授权清零；[恢复边界](../../implemented/architecture/2026-10-04-infrastructure-portability.md)部分重叠，沿用在线备份与证据保护。没有同主题活跃提案。

## Alternatives considered

- 直接改账户余额最快，但账本重建会恢复，且持续贡献余数未处理；不采用。
- 将所有批次 remaining 改零会破坏发行量减消费分配的重建关系；逐券补约 4900 万条消费分配不适合一次运营调整。采用已有账户级 adjustment 与新来源快照隔离。
- 只停止 Worker 会在恢复时补采暂停期；使用已有持久化游标前移语义，自动恢复且不补算被跳过日志。

## Consequences

全量调整期间锁定 Pulse 采集和新抽奖；不锁 new-api 主业务。未来手工回填不能跳过本次起点或向旧快照追加发券。历史累计不从零重写，新的累计从新快照和清零后的未成券余数开始。
