# Agent Note: 社区目录拖动排序

Status: implemented

## Problem

类别管理只能初始化目录，公共侧栏和标签目录分别采用推荐、固定和名称顺序，管理员不能调整呈现先后。

## Decision

复用现有类别管理与 Answer 标签身份，增加独立的展示顺序元数据。管理员拖动或上下移动后显式保存；版本条件更新避免覆盖他人排序，未知响应先读回。类别与标签各自排序，集市虚拟入口也参与类别排序。公共侧栏、抽屉、筛选及目录共用顺序；新增项目排在已配置项之后，删除项目不复活。原生 Answer 标签选择器仍遵循原生推荐设置。

## Alternatives considered

- 直接改推荐标签：能排列类别但无法表示普通标签和集市，而且改动发帖配置；因此只存展示元数据。
- 浏览器本地存储：实现简单但访客和不同设备无法共享，不满足全站呈现顺序。

## Consequences

顺序元数据独立存储，管理员不必重建标签或改动发帖规则；代价是公共页面增加一次元数据读取，配置了标签顺序的目录需完整读取后再分页，上限 10000 项。读取失败时公共导航保留原顺序；管理页拒绝加载不完整的排序。排序请求上限 1 MiB，不修改标签、推荐或权益数据。

## Verification

19 项目录测试覆盖顺序一致性、跨页排序、删除/新增项、未知响应读回与冲突；完整 `make test-community`、静态构建、插件 Go 构建与 vet 通过。独立 MySQL 8 测试验证 100 次并发重放只更新一次、不同内容并发仅一个成功，以及普通成员、跨源与停用管理员拒绝；纳入既有 forum 集成目标。Playwright 使用实际排序模块及模拟数据完成桌面拖动保存、320px 上下移动检查；生产部署与真实账号验证独立于发布。
