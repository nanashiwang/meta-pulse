# Agent Note: 优秀内容两奖项第一阶段

Status: implemented

## Problem

用户已确认周/月优秀帖子与回应评选方案，要求先推进两个奖项，暂不修改Pulse。单纯按评论数奖励无法表达内容价值，且评选与到账必须拆开。

## Decision

在Answer插件新增独立awards模块，承载提名、候选、审核、公布、撤销与月奖来源复核。应奖金额只记50/100，reward_status为deferred；不调用Pulse或授予徽章/头衔。复用正常社区身份，管理操作同时检查当前唯一角色2。

帖子提名锁用户行并在同一事务检查每日2次/每周10次、禁止自提名与唯一提名。点击周期按北京时间计算，内容按发布周归属，提名截止与审核开放共用同一时刻。周期行锁、版本与幂等收据避免并发超额或迟到覆盖，每人同奖同周期只入选一次，限周10/月5。

回应从现有answer.accepted活动读取作者触发的首次created_at，复用上游取消/重采纳保留created_at的事实；管理员同步候选，不接管原生写链路，不用updated_at猜测采纳时间。审核和公开列表核对当前采纳、内容可见性及账号状态。

月度按周一月份归属；要求该月同类所有周名单已公布，空周可公布空名单。月候选按用户聚合有效周奖来源。撤销周奖保留历史，并将相关月奖标记需复核，凭剩余来源显式恢复或撤销，不自动扣钱。

审核页按既有审核窗口启用入选、不入选和公布。不入选只需审计理由，入选同时确认两项条件；成功、校验失败及请求错误在候选卡片就地提示。确认提交但重读失败时提示刷新，不重发已确认请求。

## Alternatives considered

直接连Pulse自动发奖违背本阶段范围。用前端监听采纳请求创建候选可能丢事件或伪造时间；重写采纳接口会改变现有声望与通知语义。保留原生采纳并读取服务端首次记录，代价是管理员需同步候选且无活动记录不能补猜。按票数或字数自动选人会继续激励刷量，因此保留两项人工条件与审核理由。

## Consequences

新增6张社区表，随论坛库备份；需一起部署论坛、静态页面与网关路由。公开名单不展示未公布/无效内容。角色、资格、重复提交均由后端判断。当前不实现到账、头衔徽章、独立申诉工单或定时自动公布。

## Verification

规则测试覆盖北京时间周边界、周末提名截止、跨月周及名额金额；Go路由回归覆盖未登录、越权、跨源与伪造字段。新增MySQL集成回归覆盖额度并发、幂等、首次采纳、取消重采纳、周名额、公布冻结、月度去重及撤销复核；本机无测试MySQL，需CI执行。浏览器真实页面模块配模拟接口验证提名/额度刷新、两项审核、入选公布、版本刷新、奖励未到账文案及390px布局。不得视为生产验收。

入选时记录内容指纹，公布前比较原帖/回答及月度来源集合；正文或来源变化不能沿用旧审核直接公布，需重新审核。新增MySQL回归覆盖此路径。

本次本地结果：364项社区JS测试通过；awards与论坛插件Go测试、awards go vet通过；正式前端构建、资源闭包、路由产物与CI YAML检查通过。真实MySQL测试因未提供独立DSN跳过，已接入MySQL8.0/8.4 CI；笔记workflow验证仍因既有托管文件哈希不一致失败。无线上部署或资金操作。

## 头衔、评选勋章与手动发放补齐

用户明确闪人工发放，并要求头衔替换帖子等级旁数字。新增人工发放唯一记录及本人展示偏好；获奖记录本身作为荣誉授予事实源，重复公布不能重复授予。普通7天/月度30天按最后实际公布时间取最大，不累加；永久金色勋章按有效周/月记录计次。撤销及待复核来源停止贡献，人工发放历史不删除。

帖子原生UserCard Reputation显示位置由独立展示模块替换，Lv保留、声望数据不改；无有效选择留空。评选勋章使用独立荣誉页，不修改上游行为勋章计数，避免与其他规则耦合。个人中心增加头衔与评选勋章入口。管理员填凭据并确认人工已发放后记账状态，无Pulse调用或真实转账。

荣誉补充验证：365项JS测试通过，awards与插件Go测试通过。Chromium使用实际展示脚本验证Lv保持、声望显示位替换、月度光效、隐藏/过期；使用实际管理组件验证人工发放登记与防重复按钮。原勋章页接入金色评选勋章，独立荣誉页支持选择和来源记录。MySQL荣誉期限、周月计次、撤销及人工发放幂等回归已补充，因本机无DSN尚未运行。

## 审核提前至次周周二（2026-11-24）

帖子奖和回应奖统一在北京时间次周周二 00:00 开放审核，帖子提名和撤回在同一时刻关闭。不把提名保留到周二结束，以免提名与审核重叠；不删除已提交的提名或改写已公布记录。月奖最早开放时间随最后一周提前一天，仍要先公布当月所有同类周奖。规则与数据库集成测试覆盖周二零点前后和月奖的双重门槛。

## 评选奖励接入到账与横向布局（2026-11-24）

早期的手动登记改为公布后主动点击「发放」。复用限时赠礼到账机制，而不新增收款人、金额均可由请求指定的发放能力；服务器使用原有奖项和冻结的推荐奖励，一次创建唯一且不可改写的发放凭据。管理员权限、周期版本、收款人绑定和历史手动记录均在提交时核查，到账前后状态分开，撤销评选不撤销已提交金额。

桌面端分开显示内容、推荐名单、奖品和操作，理由在管理操作内按需展开；移动端单列。论坛与奖励后台的独立 MySQL 回归覆盖已公布资格、双方收款、精确金额、重复重放、历史手动防重发与到账确认；前端覆盖显示与交互。

## 公开榜单按期归档（2026-11-24）

没有选期次时，公开评选按已选周／月和奖项展示已公布的期次，按开始日期倒序分页。保留带期次的直接链接、管理员审核和个人提交的单期行为。沿用单期的内容、采纳和账号可见性检查，而非为前端猜历史日期或把多期奖项展平成一张名单；分页以完整期次为单位，避免把同一期奖项拆散。窄屏单列，宽屏同一期内可并列展示两张获奖记录。

MySQL 回归覆盖开始日而非公布日排序、隐私过滤、空期次、跨页和不同奖项；前端覆盖无日期浏览、精确跳转及筛选重置。
