# Agent Note: 社区四类排行榜

Status: implemented

## Problem

现有页面仅近七天声望榜，用户要求增加等级、发帖、回答榜，并希望每榜展示前100人。

## Decision

保留 Answer 近7天声望增长接口及 Top100 补丁；新增公开 GET /answer/api/v1/metar/ranking?kind=level|posts|answers，复用独立于 Pulse 的 experienceStore 连接。等级使用已入账 metar_exp_account.balance，经 LevelFor 显示等级，同级按经验；发帖统计 question status 1/2 且 show=1，回答统计 answer status=1 且父帖公开有效，不统计 comment。三榜均累计、仅正值，仅活跃邮箱已验证用户，角色2/3排除，同分按数值用户ID升序，先过滤再LIMIT100。

只返回公开用户名/显示名/头像、等级和统计值；无邮箱、绑定ID、日志或资金字段；计数以字符串传输，不依赖浏览器整数精度。参数白名单与重复键校验，查询5秒超时，失败503不返回部分结果；不写排名表，不更改经验或奖励。等级依赖经验投影已有更新节奏，不实时触发积分采集。

前端四榜切换保留board查询参数，默认每页100，分页10/20/50/100。工作人员沿用原接口单列。切换清空旧榜、取消旧请求并用序号拒绝迟到结果；失败保留当前榜标题与重试，不冒用前榜分数。level显示Lv与EXP，其余显示对应数量。普通用户没有达到上榜条件时显示未入榜，不用零值补位。

## Alternatives considered

- 前端拉全量用户逐个查询：请求放大并可能暴露非必要字段，无法可靠得到全站排名。
- 复用Answer声望作为等级：两套积分语义不同，不能混用。
- 新建排名持久表：增加同步一致性成本，当前规模先用受限只读聚合；扩大规模后需根据查询计划决定索引/缓存。

## Verification

77项论坛前端测试通过；插件及growth Go测试通过（MySQL集成项未配置DSN，跳过）。新增MySQL用例覆盖人员状态、隐藏/删除父帖、独立回答统计、等级边界、稳定排序与100人截断，已纳入现有growth集成测试范围。浏览器模拟API验证100行、四榜切换、迟到等级响应不能覆盖回答榜，375px长整数无横向溢出。资源完整性检查通过。未执行生产数据库写入或完整Docker构建。

## Consequences

需部署新版forum；先更新前端而后端未更新时新增榜显示加载失败，不能伪造数据。声望榜仍为7天，另外三榜是累计榜，页面明确标注。本文不授权部署，也不改变既有待提交勋章提示工作。
