# Agent Note: 社区经营指标与用户运营标签

Status: implemented

## Problem

运营需要判断注册增长、有效活跃、注册转化、留存、内容供给与回应情况，并为社区成员添加运营标签。现有账号状态与成长经验不能替代阅读活跃；此前未采集的访客轨迹也不能从帖子统计推算。用户授权完成后提交、发布并部署 M社服务器，工作日明确采用中国法定日历并包含调休。

## Existing capabilities and impact

Answer 持有账号、注册时间、帖子、回答和管理员角色；现有插件提供独立 MySQL 表、实时管理员复核及同源写保护。METAR 壳与原生 Answer 页面分开构建，采集须覆盖两种入口。现有原生后台处理账号治理；新的经营页复用其身份，运营标签不改变权限、封禁、经验或 Pulse 资格。

活跃笔记检索 `经营|留存|统计|标签|analytics`，未发现经营指标的拥有者；[类别治理](../../implemented/feature/2026-10-09-community-taxonomy.md)仅拥有内容标签，[聊天](../../implemented/feature/2026-10-10-community-chat.md)仅提供可复用的管理员与数据库边界，均保留。不得读取私聊正文或引入 new-api relay 依赖。

## Decision

新增管理员经营页，复用 Answer 事实计算用户与内容指标。采用上海时区，按完整自然日显示 DAU/WAU/MAU、注册队列 D1/D7/D30、注册后七个法定工作日有效活跃天数及样本数。有效活跃是前台内容阅读达到 30 秒或有效发帖/回答，签到和抽奖不自动计入。历史采集不足、窗口未结束与日历未覆盖均显式标记，不能伪装为零或已流失。

浏览器通过独立同源接口异步上报有限种类事件；匿名访客使用第一方随机 HttpOnly Cookie，登录用户身份只从已校验 Answer 会话取得。只保存日级去重、首次观察与注册关联，不保存 IP、完整 URL、搜索词或私聊内容。注册耗时仅对可关联的新注册者计算，同时显示匹配覆盖及固定窗口转化率；未登录的既有账号不算新注册。

用户运营标签仅管理员可见，限制标签长度与数量，实时鉴权、事务审计和版本冲突保护；不修改 Answer 内容标签。统计与采集失败不得阻断浏览、登录、发帖或模型调用。

## Alternatives considered

- 只用现有账号和帖子聚合：无需新增采集，能准确得到内容供给，但缺少纯阅读用户、匿名转化和有效活跃留存。
- 引入外部统计产品：有现成报表，但仍需社区身份、业务口径和管理员标签集成，并增加外部数据与运维边界；本次复用插件与数据库。
- 把签到/抽奖作为活跃：数据现成，但会把权益操作当作社区价值；单独保留这些已有业务，不用于本次有效活跃。

## Testing

- Go 路由与 MySQL 测试覆盖匿名/普通成员拒绝、撤销管理员权限、伪造 user_id、跨站写和严格 JSON。
- 专用 MySQL 8.0 测试库通过 100 次并发重复上报和标签保存、午夜边界、D7 精确日期、队列成熟度、旧账号不算新注册、转化覆盖、标签冲突与审计；CI 复用 8.0/8.4 矩阵。法定假日/调休和未知年份有回归。
- 共享采集脚本的前后台、30 秒阈值、隐私偏好、失败退避回归通过；两端资产均包含同一脚本。Playwright 以本地模拟 API 验证真实壳层管理员页面、标签保存、桌面/手机、中英文及深浅主题。网关真实容器验证 Cookie 路径隔离与身份头清除。生产发布和部署仍须分别核实，浏览器模拟不证明线上身份会话。

## Consequences

匿名识别受清理 Cookie、跨设备和拦截影响，只报告可观察范围；前端活跃是经营估计，不用于奖励记账。日历按已核验的官方年度通知版本化，未公布年份不能按普通周一至周五冒充法定工作日。统计读取必须有时间范围与超时限制，避免影响论坛主业务。

日级聚合和审计目前随 Answer 备份保留，不自动清理；90 天查询窗口与行数/超时限制控制读取成本。规模扩大时须增加可重建汇总与保留策略。完整口径见 docs/COMMUNITY_ANALYTICS.md。
