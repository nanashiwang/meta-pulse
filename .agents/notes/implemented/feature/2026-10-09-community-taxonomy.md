# Agent Note: 社区类别、标签与公开申请

Status: implemented

## Problem

METAR 的 `/topics` 只有前 48 个 Answer 标签，讨论列表不区分类别与交叉标签。用户要求借鉴 Linux.do 的类别和标签，先提供起步集合，并允许成员申请新增。

## Decision

复用 Answer 的管理员推荐标签作为类别、普通标签作为交叉标记。起步集合参考 2026-10-09 实际查看的 Linux.do 公开导航：12 个一级类别、资源荟萃下的网盘资源，以及 7 个常用标签。描述采用本项目自写文案，不复制帖子、用户或统计。管理员显式初始化，合并已有设置；升级不自动写生产数据。

类别目录、讨论筛选、普通标签分页和申请入口共享一个模块。新增申请通过 Answer 原生 `prefill` 发帖，保留登录、激活、验证码、草稿、审核及通知；管理员在原帖说明结果，通过原生标签和撰写设置启用，不另建工单或身份系统。只有后台推荐标记决定新类别，用户的申请帖和自建普通标签不自动成为类别。管理员初始化逐项查询已有标签，未知写入结果先停止并允许重新查询恢复，不覆盖已有介绍或删除标签。

## Alternatives considered

- 单独建类别表、审批表和发帖 API：能强制单一类别，但重复 Answer 内容与权限流程，且需要迁移既有帖子；起步阶段不采用。
- 纯前端写死名称并当成已上线类别：改动少，但会让未创建的类别看似可用，管理员后续扩展也需要发版；只把静态集合作为待初始化预览。
- 使用保留标签表示类别：能限制标签，但 Answer 会限制普通成员使用保留标签；类别使用推荐标签，保留标签维持原有治理语义。

## Verification

- `make test-community` 覆盖初始化合并、响应丢失后恢复、重复执行、保留标签/同义词冲突、权限、并发设置漂移、写后核验失败、模板编码、真实目录介绍、分页和 HTML 转义；`make build-community` 通过。
- 隔离的本地 Answer 实例验证真实接口：保留已有推荐标签、自定义名称/介绍及其他撰写设置；完成初始化后重复执行零写入。原生安装自带标签也继续保留。
- 真实 Answer 浏览器登录后，申请链接正确预填中文标题、正文和运营反馈标签，停在原生编辑器，不发布测试帖子。
- 生产壳搭配本地模拟数据验证空目录、初始化、类别筛选、排序分页及刷新、85 个标签翻页、普通成员/未激活管理员/访客管理页拦截，以及分类接口失败时仍显示讨论。桌面、390px/320px、中英文及深色主题检查通过，无横向溢出。
- `go test` / `go build` 显式论坛插件模块通过；Nginx 配置与 SEO 网关回归通过。生产升级及普通生产账号验收独立于本次发布。

## Consequences

Answer 推荐标签允许多个，不等价于 Discourse 的严格单类别/子类别模型；网盘资源的归属仅作目录展示。原生设置 API 无原子版本检查，初始化前后重新读取并核验；管理员应避免与原生撰写设置并发修改。申请审核依靠原帖回复，不产生自动审批状态。公开类别目录额外读取各标签的当前介绍，读取失败保留类别链接并用通用提示，不拿起步描述替代管理员修改后的内容。只有未初始化预览翻译静态名称和描述，真实标签内容保持原文。
