# Agent Note: 编辑器自动导入外链图片

Status: implemented

## Problem

粘贴文章只保存外部图片地址，来源限制或失效导致裂图；用户希望自动下载并上传，免逐张保存。Answer 1.7.1 原生编辑器已处理图片文件上传与富文本转 Markdown，但不下载外链。

## Decision

使用官方 editor 插件槽，在原生 CodeMirror 正文变化后识别图片节点，后台逐张下载并调用原生 `/answer/api/v1/file` 上传。成功才更新当前仍存在的图片地址，不改用户同时编辑的文字、不重新发布帖子。引用式图片转为等价内联图片，不改变普通链接或代码示例。编辑已有正文也自动导入；失败保留原图并显示重试。

下载端仅认证且实时活跃的 Answer 用户、同源 POST；拒绝查询参数。仅 HTTPS 标准端口、公开 IP，DNS 解析结果全部校验并固定到连接地址，逐跳校验重定向，不透传凭据、不走环境代理。限制大小、像素、时间、并发和每账号速率，仅返回已识别的光栅图片。上传仍由 Answer 校验权限、大小和类型、记录文件并选择已有 Storage；插件不直接写文件或绕开孤儿文件清理。不会自动批量扫描历史帖子。

图片响应通过当前 ResponseWriter 写入，不预设未压缩 Content-Length。Answer 1.7.1 全局 Brotli 与 Gin 1.12 的 Data renderer 组合会先移除再写回原始长度，浏览器声明 `Accept-Encoding: br` 时收到截断响应，即使下载接口已返回 200 也无法进入原生上传。传输验收必须使用真实 HTTP 服务与 Answer 同版本中间件，并覆盖反向代理和完整字节比对；Recorder 的状态码不足以证明图片可用。

### Existing note review

基础设施可迁移笔记关于附件 Storage/备份的决定部分重叠且保持成立；本能力复用它，不新增存储事实源。Pulse 视觉图片与服务器迁移验收记录无关。没有现成导入功能或待实施提案。

## Alternatives considered

- 仅开启外图显示或去 Referer：改动少，但来源失效与网络故障仍在。
- 浏览时图片代理：旧正文无需修改，但每次浏览仍依赖远端，下载接口更容易被滥用。
- 改 Answer 源码：直接接入上传服务较短，但违背不 Fork 的边界；官方 editor 扩展与原生上传接口足够。
- 前端直接 fetch 外站：可省下载服务，但跨域策略使常见来源无法读取图片内容。
- 网关仅对图片下载禁用压缩：可以绕开长度冲突，但直接访问 Answer 或不同网关仍会失败；响应层消除错误的原始长度，沿用宿主正常压缩协商。

- 完整 Answer 1.7.1 Docker 镜像构建通过。隔离 MySQL/Redis/Answer 中，用户提供文章的 13 张图片全部可定位；两张真实微信图经过下载、原生上传、正文替换、发帖和刷新后正常显示，数据库存在原生文件记录。
- 原生回答区富文本粘贴两处相同来源，仅新增一条上传记录，两个预览均显示本地图。390px 窄屏无横向溢出；失败保留原文并可重试。界面复用原生深浅主题。
- 本机代理 DNS 返回 198.18 保留地址，被安全拒绝；隔离容器使用公网 DNS 返回的真实 IP 验证外部下载，没有放宽生产地址校验。
- 后续串行化同页多个编辑器、片段归一化去重由自动回归覆盖；最终发布工作流重新构建全部提交代码。发布不代表生产部署。
- 生产 v0.2.70 暴露浏览器 Brotli 响应截断：13 张图片下载均为 200，但网关报告 upstream prematurely closed connection，编辑器保留外链。新增真实 HTTP + Brotli + 反向代理回归先复现 unexpected EOF，修复后小图、大图在 identity/br 两种传输中逐字节一致；没有把状态码成功当作导入成功。

## Consequences

自动导入增加网络与附件容量；导入成功而未发帖的文件沿用 Answer 清理。每页多个编辑器共享串行上传队列；服务端单进程下载限流不作为跨实例全局预算。来源拒绝访问时仍可能需人工上传。现有上传响应丢失不能承诺文件级 exactly-once，但正文仅使用确认成功的 URL。对象存储的外域 URL 在当前编辑器会话内去重；再次编辑时可能重新导入，默认同源存储不受影响。

下载与最终上传分两步，使插件可以复用未对 Go 插件公开的上传业务和文件记录；代价是图片字节经过浏览器中转一次。未增加独立存储、后台历史文章迁移或财务依赖。基础设施备份规则见[原附件边界](../../implemented/architecture/2026-10-04-infrastructure-portability.md)。
