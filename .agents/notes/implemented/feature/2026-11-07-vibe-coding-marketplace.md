# Agent Note: Vibe Coding 集市

Status: implemented

## Problem

成员需要集中发现和体验 AI 辅助开发作品，并将想法讨论关联到后续实现。普通类别列表无法表达用途、体验方式、费用和源码。用户已授权将产品方案实现、提交并部署到生产。

## Existing capabilities and impact

已核对能力地图、共享路由、taxonomy、Answer 会话及插件注册：推荐标签仍负责普通类别，原生帖子、账号、评论、收藏和治理继续由 Answer 提供。集市新增发现元数据与审核，覆盖壳层/原生导航、类别目录、列表、详情、投稿维护和管理员审核入口。

检索活跃笔记 `集市|marketplace|vibe|类别|社区任务|赠券`：[类别治理](2026-10-09-community-taxonomy.md)和[展开侧栏](2026-10-15-expanded-taxonomy-sidebar.md)部分重叠，保留其真实推荐标签和有界预览，另加固定功能入口；[社区赠券](2026-11-06-community-tickets.md)仅经济边界相关，沿用原任务规则。不完整取代其他决定，原集市 proposed 随本实现迁移。

## Decision

介绍正文先在 Answer 原生编辑器发布，再由作者选择本人帖子或粘贴地址补充集市信息。此两步流程保留原生验证码、激活、草稿、内容审核和通知，避免正文跨系统双写及重复创建。原帖按 Answer 规则独立可见；集市草稿、待审链接和审核说明仅作者/管理员可读。每帖只收录一次，类型和原帖关联创建后不可改；一个想法可关联多个项目。

Answer 插件在 Answer 数据库维护 `metar_market_item`、actor、request、audit。item 的 entry_json 是投稿，live_json 是已审核快照；首次提交和每次元数据更新均人工审核。审核期间旧 live 继续公开；通过后替换，作者或管理员下架清除 live。公开读取实时联查原帖归属、状态、show 和作者激活状态，原生删帖、隐藏或封禁不能绕过。管理员权限同时校验会话和当前数据库角色。

本人写操作按永久 actor 行串行化，使用规范化 payload 的 fingerprint 与 actor + Idempotency-Key 恢复结果；同 key 异 payload 冲突。元数据、计数、审核前后值和回执同事务，空回执预留可以续办。浏览器发送前保存原请求，未知结果只重试原 key；换号不可发送上个账号的请求。写接口检查同源、自定义请求头、严格 JSON 和可信 Answer 会话，拒绝浏览器自报 user_id。

收录标准 GitHub 仓库与公开 HTTPS 演示。演示链接拒绝凭证、query、fragment、字面 IP/内网/本站域名；不抓取或反代目标。作者声明费用、AI 依赖、数据去向及嵌入许可，管理员核准后访客才可点击站内体验。使用前重新获取 live，iframe 仅允许 scripts/forms，不允许 same-origin、顶层导航、弹窗和敏感设备权限，使用 no-referrer；保留外站回退，不把 load 事件当作运行成功。论坛 token、API Key、余额授权不进入 iframe。

集市浏览、投稿、收藏和运行不增加贡献、Ticket 或奖励来源。原生讨论符合已有社区任务时仅按既有事件计一次，模型请求不经 Pulse。完整用户流程及首版范围见[产品文档](../../../../docs/VIBE_CODING_MARKETPLACE.md)。

## Alternatives considered

- 只用普通标签与发帖模板：可迅速试运营，复用最充分，但费用和体验方式埋在正文，无法支持结构化发现和已审核运行入口。保留标签和原生模板作为正文入口，扩展元数据。
- 独立正文、账号和评论系统：数据模型自由，但会重复身份、内容治理和互动，且产生跨系统一致性成本；继续由 Answer 承担这些事实。
- 首版托管源码或统一反代 AI：能统一体验，但要求构建隔离、预算、运营和新的安全边界；首版使用作者已有部署，不扩展为模型代理或代码托管平台。
- 直接编辑已发布演示链接：维护成本最低，但新地址可绕过审核；使用独立 live 快照，代价是更新需再次审核。

## Verification

- `make test-community` 通过：8 项 Python、147 项前端、10 项编辑器、6 项论坛定制及 43 项原生插件测试；覆盖请求恢复、换号、私有路由、转义和相邻导航。
- 隔离 MySQL 8 实际执行项目/想法发布、审核、live 保留与替换、权限治理、幂等恢复及 100 次并发重放；通过完整论坛插件 Go tests、集市 race 和全插件 vet。测试容器使用独立 tmpfs，不接入生产数据库或卷。
- `make deploy-test` 与 `deploy/config-test.sh` 通过；生成路由/主题检查、gofmt、URL 校验标准库测试及 diff 检查通过。配置检查使用公开 fixture，不读取真实生产配置。
- 浏览器在生产壳的隔离预览中检查列表、详情、费用/数据、GitHub/原生讨论链接、投稿字段及项目/想法切换。真实生产更新、匿名接口和登录交接在部署后另行核验，不将预览数据或隔离测试视为线上真实投稿。

## Consequences

两步发帖增加一次返回操作，但原生编辑、治理与互动保持单一事实源。元数据待审并不使原帖私有，投稿页明确说明。新版保留已审核链接直到更新审核完成，减少中断；已有 iframe 不可远程回收，新的体验点击会重新检查。

首版不含封面上传、自动仓库解析、自动演示探测、源码托管或交易；精选、审核和演示可用性由管理员维护。部分第三方应用不能在最小 sandbox 内工作，应使用外站入口。域名校验不承诺第三方内容可信或永不改变，人工审核和内容治理仍有持续成本。
