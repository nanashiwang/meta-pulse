# Agent Note: 用户管理券与互动统计

Status: implemented

## Problem

用户管理缺少券和互动统计，已有列设置与受保护绑定批量查询可以复用。既有用户列表笔记拥有布局，本记录只定义新增统计契约；手动赠券与社区经营笔记保持各自范围。

## Decision

扩展现有列表及绑定批量查询，社区统计读 Answer，券统计经管理员签名读 Pulse。券总量为历史正向发券账本，剩余为所有规则版本券账本净余额。主帖统计有效主帖；获赞统计未取消的主帖正赞；评论包含有效回答及楼内评论；主动点赞统计有效正赞。分享统计上线后主帖分享按钮点击次数，允许重复，匿名也可点击，不证明外部实际转发，不补造历史。失败显示缺失值，不伪装零。生产约 340 万条账本上原汇总超出 Pulse Client 的 3 秒超时，因此增加 `(user_id, asset_type, operation, amount)` 覆盖索引并固定查询使用该索引，保留账本净余额与累计正向发券口径；不延长超时掩盖扫描。发帖数在插件统计暂不可用时使用原生列表已返回的 `question_count`，无需等待 Pulse；其他社区计数仍由 Answer 实时查询。

## Alternatives considered

- 直接让 Answer 连接 Pulse 库可减少请求，但越过事实源服务边界，不采用。
- 重写管理页可自由布局，但重复已有权限与用户操作，不采用。

## Testing

七列接入既有列开关；批量上限 100；管理员身份实时复核；社区和券故障独立降级；分享不发券或经验。Go 测试、race 路由测试、MySQL 真实计数回归、Answer 补丁应用、Answer UI 正式构建与隔离源码的社区前端回归通过；Pulse 故障时社区统计保留的路由回归通过。MySQL 覆盖券铸造、赠券、调整、消费、过期、撤销与未获券用户；社区覆盖取消点赞、删除帖子、回答与评论、重复分享及跨站请求。

生产只读诊断：Pulse 统计请求约 2990ms 后 context canceled / 503；Answer 原始查询返回当前页 100 人，耗时约 60ms。

## Consequences

索引增加账本写入与磁盘成本，但避免管理查询回表扫描历史金额记录；迁移不修改账本数据。历史分享无法恢复；统计增加数据库读取成本，批量查询仅限当前页。完整论坛 Docker 构建在本地因 Docker Hub 基础镜像元数据请求 503 未完成；Answer UI 和 Pulse 二进制独立构建通过。
