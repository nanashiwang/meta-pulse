# Agent Note: Token 农场币换论坛券

Status: implemented

## Problem

农场币在独立 SQLite，论坛实际可用券来自 Pulse Ledger 和发行批次；用户授权以一万农场币换一券。此来源独立于已退役的消费换券。

## Decision

农场只接受当前兑换序号，在一个事务内核查余额、扣币并持久化随机订单。每个玩家最多一笔待确认订单。论坛同时验证 Answer 会话、实时绑定和农场针对双方身份及该订单的独立签名，再转发给 Pulse。Pulse 以全局订单号去重，并绑定收款人；同一事务写 ticket_bonus、券批次、审计及可重放的成功回执，不产生贡献。只有核对匹配的回执后，农场才显示到账。

## Alternatives considered

[人工赠券](2026-11-09-admin-ticket-grant.md)需要高权限；[签到回执](2026-11-06-community-tickets.md)是限额活动来源。两者都不能代替农场付款证明。订单号或普通用户会话单独使用也不能证明已扣款。

## Consequences

两套账本不共享事务。超时不直接退款，也不换单号；后续已登录的机房访问继续核对原单。未开通不受理新单；回滚前应先对账并备份，不能单独回退兑换数据库。签名私钥只在农场本机，论坛随版本携带非保密的验证指纹，不再要求单独修改论坛主机配置。新版本仅信任当前版本的付款证明，不接受旧格式。更换签名身份须经新的论坛版本审查。农场先限制为指定机房的一笔验收；在原单确认到账前，即使选择全服模式也不受理新单。

## Verification

农场 SQLite 自动测试覆盖扣款边界、百次重复请求、丢响应及恢复、绑定身份和回执匹配；Go 测试覆盖论坛与 Pulse 的认证入口。已在隔离 MySQL 8.0 执行百次并发回放：同一已付款订单只生成一张券与一个可用批次，换账号重放被拒绝。该验证未使用生产玩家余额。
