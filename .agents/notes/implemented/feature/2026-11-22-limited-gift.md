# Agent Note: 限时赠礼与到账分项统计

Status: implemented

## Problem

管理员需要在活动管理中向满足昨日条件的绑定用户限时赠礼，不扣抽奖券，并能区分已领取与实际到账。

## Existing capabilities and impact

复用活动管理权限、不可换绑身份、Pulse 动画、论坛经验以及既有券与闪结算账本。普通报名活动和签到不会触发赠礼。

## Decision

同一时间一轮，创建时封存规则；服务端生成并持久化每人的金额后才异步交付。论坛将已提交的领取记录原子投递到专用非网页共享卷，Worker 只读挂载、核对记录并幂等处理。回执确认后才清理投递副本；丢失副本从论坛事实记录重建，不增加可指定奖品或收款人的网络发放入口。统计只计确认回执。对每个奖品保持稳定的来源标识，服务重启和丢响应都不能重抽或重发。昨日统计按北京时间半开区间并使用严格大于。

## Alternatives considered

普通 Pulse 抽奖会消费券且无法表达组合礼，不复用其扣券动作。报名人数不等于已发金额，浏览器余额或本地随机结果也不能作账。

## Verification

独立 MySQL 的并发领取、原单重试、门槛边界、未绑定、到账统计及管理员隔离测试；另有界面和服务回归检查。

## Consequences

活动默认关闭。上游不可读时资格不放行，到账确认滞后时保留待到账记录而不是报告成功。

## 多组条件与优先级

新活动可封存最多八组独立门槛与奖品，按显示顺序匹配，首个满足组就是唯一奖励。不采用叠加或按奖品价值推算优先级，避免意外多发和不同奖品单位的歧义。无记录按不满足门槛处理；若可能优先命中的规则所需数据暂不可读，则不发放，不自动降级。旧活动继续按原单组规则执行；原领取回执仍优先于重新判断。

Go 测试覆盖重叠命中、第二组命中、严格边界及外部数据异常；隔离 MySQL 验证两组都匹配时并发领取只保留排名第一组的一份奖励；浏览器验证规则可上移且按显示顺序提交。

## 管理员活动概览

复用活动管理的服务端角色判定，仅在进行中的活动给管理员返回领取总人数和本人回执。查看权限不授予领取资格；不满足或无法核实条件时保持禁领。赠礼使用 Pulse 动画，但不参与普通抽奖按钮状态同步，避免误显示扣券。MySQL 测试覆盖管理员未绑定、有资格、重复查看和活动结束的情况；浏览器验证按钮、灰色状态、领取人数及获奖回执。

## 互动门槛包含设定值（2026-11-23）

管理员要求点赞、评论达到门槛即可通过。创建时封存互动比较方式，避免正在进行的活动突然扩大参与范围；已有规则保持原比较方式。API 消耗仍严格大于，不把无记录当作零。测试覆盖新旧相等边界、低于门槛和消耗边界，隔离 MySQL 验证新活动可在互动次数恰好达标时领取。

## 抽奖券可抽到零张（2026-11-23）

允许抽奖券随机下限为零、上限仍须为正；经验和闪电不改。领取回执记录零张是否来自抽取，以区别未配置抽奖券。零张不进入交付队列，仍占用本轮唯一领取；同批其他奖品照常交付。隔离 MySQL 验证零张回执重放和管理明细，浏览器验证零结果开奖及刷新显示。

## 每组领取人数上限（2026-11-23）

复用赠礼轮次锁和不可变领取回执，不新增共享计数器或按发放状态扣名额。规则列表可各自限额，已满规则不读资格数据；并发提交在轮次锁内复核，发现名额用完时跳过该组重新匹配。零券有效回执也计数。历史活动不追溯限额或档位，已领者始终重放原结果。相比独立计数器，不需要维护第二套名额事实；按到账扣名额则会让待到账记录造成超领。

Go 单元测试覆盖跳过资格读取、下档门槛、全满和输入边界；隔离 MySQL 验证两个请求同时看见最后一个名额时仅一人进入首档，另一人匹配次档，管理员明细可见两人的档位；前端测试覆盖每档独立限额与留空。
