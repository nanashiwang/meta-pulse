# Agent Note: 讨论首页连续滚动加载

Status: implemented

## Problem

讨论列表每二十条要求翻页，打断阅读。用户要求首批五十条，随后随滚动每批十条追加。

## Decision

在现有 questionsPage、questionRow 和 Answer listQuestions 上扩展首页及共用类别/标签筛选列表，移除页码。首批 page=1/page_size=50，后续 page=6/page_size=10 起递增，保留原排序、置顶与权限。按字符串 ID 去重；单路请求、导航/身份/语言作用域校验和生命周期清理防止乱序追加。底部观察器提前四百像素加载，错误暂停并提供重试，无观察器时保留手动加载。空页或末页结束。

浏览器整页恢复且 URL、语言、会话一致时保留已追加 DOM 和下一页位置，不用新的五十条截断原阅读位置；冷恢复先读五十条再按保存的加载进度每次补读十条，逐批恢复滚动；失败暂停、重试继续。history state 只存 URL、语言、下一页和滚动坐标。筛选切换重新加载首批。旧 page 参数不再选择分页。不持久化内容或凭据。

## Existing capabilities and note audit

复用 Answer 页码接口（已核对 1.7.1 无五十条限制且置顶属于同一分页）、静态构建、讨论渲染和现有导航序号。影响 /、/latest、兼容别名、/topic/:slug；收藏、搜索与后台保留原分页。

[恢复首页共用列表](2026-11-11-restore-community-feed.md)的路由归属保留，分页交互由本篇接管。[讨论切换](../bug-fix/2026-10-15-discussion-switch.md)的旧列表保留与乱序防护继续适用；[首屏恢复](../bug-fix/2026-10-05-community-loading-shell.md)的讨论页同 URL 后台替换选择被本篇调整以保留滚动深度，其他页面不变。其他模型榜/后台分页笔记无关。

## Alternatives considered

- 首批五十、后续仍请求五十再分段显示：可减少请求，但额外下载用户可能不看的内容，不符合每批十条增量请求。
- 新增服务端游标：可稳定并发内容更新时的跨批次快照，但需要改变上游接口及排序契约；本次复用页码，去除重复，实时增删导致的页间位移仍是既有接口限制。
- 只提供加载更多按钮：兼容简单，但不能实现用户要求的连续下滑；仅用于降级和重试。

## Verification

11 项新增流控制回归覆盖 50→60→70、尾页、空列表、重复大整数 ID、并发滚动、失败重试、无观察器、作用域变化、晚到响应、拒绝访问、DOM/冷历史恢复及恢复中失败重试。完整 make test-community 与静态构建通过；浏览器合成数据验证 50→60→70→80→83、503 重试、筛选重新首批、慢响应不混入新筛选、原生详情返回 83 条及滚动位置，390px 英文深色无横向溢出。截图保存在忽略目录 output/playwright/discussion-stream-*.png。

## Consequences

页码接口的实时排序不是快照；新回复/删帖可能移动后续位置，去重不保证动态数据零遗漏。长时间阅读保留已展示 DOM，会增加内存；不为本次引入改变浏览器查找/返回语义的虚拟列表。
