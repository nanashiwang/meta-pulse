# Agent Note: 社区导航 PR 集成

Status: implemented

## Problem

PR #1 统一原生社区入口、个人中心和声望排行榜，但旧网关断言导致 CI 失败，旧 Hash 书签与无历史返回还需兼容；模型榜标题也意外回退。

## Decision

首页选择已由[恢复首页共用讨论列表](2026-11-11-restore-community-feed.md)取代，下述原生首页方案保留为历史决定；顶栏、个人导航与声望榜继续适用。

复用 PR 的 Answer `/questions` 社区入口、`/users` 近七天声望榜及 `/me` 专用导航。根路径、latest/discover 重定向保留查询；原生桥接在 `/questions` 恢复旧 Hash 壳层入口，不接管敏感回调。移除公共旧侧栏但保留管理后台导航；Answer 后台与公共页共用 `#pcSideNav` 容器，隐藏规则必须排除包含 `#adminSideNav` 的容器，且 `.admin-container` 存在时保留原生手机菜单按钮，由 Answer 的断点控制桌面栏与抽屉；管理入口仍检查真实身份与角色。保留模型评分榜标题及已移除近期模型模块的决定。

个人中心侧栏移除“我的集市发布”；“签到抽奖”使用站内 `/pulse`，不依赖元衡控制台地址是否配置。页面返回按钮以 `/me` 为基准，社区壳层与 Answer 共用 `back-button.css`；聊天返回列表、错误页返回入口使用同款描边按钮，原目的地和移动端显示规则保留。主页顶部返回按钮使用不可见占位，不移除布局空间；讨论页保留与 marketplace 一致的顶部搜索框，导航文字使用固定字重，避免路由激活状态造成横向偏移。

排行榜仅使用 Answer 原生前 20 条，剔除工作人员后按返回顺序展示，分页不冒充全站 Top500。数据与权限事实源不变。

## Alternatives considered

直接合并可最快交付，但留下失败检查与已确认回归；只修测试不能解决历史链接丢失。另建排行榜后端可扩大人数，但超出 PR 范围，保留当前上游数量限制。

## 返回个人中心与头像链接修复（2026-11-13）

原生 /admin 及其子页和社区壳层管理页顶部返回统一到 /me；左侧“返回网站”和站名仍保持首页语义。头像在 /me 也保持带 data-router 的真实链接，避免顶部复用时把不可点击 span 带回其他路由。原目的地特例不依赖浏览器历史，保留首页返回占位。

新增回归覆盖 me 头像随顶部复用后仍有有效链接、壳层后台返回以及原生后台返回和非管理路径边界。

## 区域来源返回与循环修复（2026-11-13）

旧版每个路径只保存一个来源，通知→帖子A→用户→帖子A会覆盖第一次来源，形成帖子与用户互指。返回不会消费记录，sessionStorage 会让循环持续。

共用 return-navigation.js 现在在每个浏览器 history.state 中保存版本化访问快照（当前 URL、步数、最多 50 个前序位置），重复 URL 按不同访问处理。pushState 只在调用成功后增加位置，replaceState 保留步数，保留原 state 中的路由与滚动字段；popstate 与 BFCache pageshow 恢复对应历史快照。返回使用 history.go 到前序位置，不创建新的访问。/admin 子页合并为一个返回区域，但保留实际浏览器步数，从任意子页跳回后台进入前的页面。列表查询参数保留，现有 router.position 恢复列表滚动。

跨文档链接点击仅保存内存意图，在 pagehide 才写入一次性会话交接；目的页仅在 URL、同源 referrer、30 秒时限均匹配且没有现存历史快照时接受。刷新、前进后退优先使用原历史快照。取消编辑器离开不触发 pagehide，不能污染当前返回链。特殊头像编程跳转复用 remember 意图接口。旧 v1 来源字典被删除，不迁移循环。无可信记录、站外或认证页面来源时使用安全默认入口；不伪造历史。未经过捕获链接的跨文档编程跳转不推断来源，使用默认入口。

备选：单纯改为无界 sessionStorage 栈无法同步浏览器前进后退；检测环并回首页虽能停止循环，但丢失实际进入路径；直接无条件 history.back 无法跳过后台兄弟页且可能退到站外。因此选择每历史位置的快照与已知步数。需要 History API；存储不可用时站内 SPA 历史仍可工作，跨文档来源缺失时保守回默认页。

验证：318 项前端/插件测试与正式构建通过。回归覆盖二页/三页循环、重复 URL、浏览器前进后退、刷新、后台分组、查询参数与滚动字段、无效记录、取消跳转和跨页交接。真实 Chromium 多文档验证通知→帖子A→用户→帖子A依次返回用户→帖子A→通知；个人中心→后台用户→后台设置→刷新后一次返回个人中心。未修改内容、身份权限或财务数据。

## 固定页脚边缘与正文留白修复（2026-11-13）

固定页脚原有 bottom:12px、左右 inset，以及手机 bottom:67px，使滚动内容从底栏边缘漏出。页脚背景现在贴合桌面视口边缘；个人中心贴合 232px 侧栏边界，手机贴合 55px 加安全区的底部导航，仅在导航实际显示的 580px 断点启用该偏移。内容内边距保留，不以额外遮罩覆盖正文。

复用 renderView 为每次页面渲染测量实际页脚高度，并用 ResizeObserver 跟随换行、语言与窗口变化；切页断开旧观察器，无页脚时清零。正文底部留白为页脚高度加手机导航高度与 24px 间隔；选择器覆盖旧 html:not(.preview-tools) 页面规则，避免原 82px/38px 留白遮挡末项。保留固定页脚而未改为随文流动，是为了保持现有入口行为；不使用固定猜测高度，因为手机及英文链接可能换行。

验证：235 项前端回归通过、正式构建通过。完整构建 CSS 下对 320/375/580/600/767/768/1440 宽度、浅深主题、有无个人侧栏共 28 组进行浏览器布局检查：底栏边缘无缝，最后内容可滚动至底栏上方。用本地构建替换资源、读取线上匿名数据，检查 latest/pulse/me/tos 桌面与手机底栏；marketplace/models 无此页脚，不添加额外固定栏。未执行登录态后台业务操作，后台共享底栏由相同渲染入口与布局组合覆盖。

## 设置分支返回（2026-11-14）

设置页曾遗漏区域归并，导致资料/通知/账号/界面子页按每次访问后退，与后台行为不一致。现将 `/users/settings` 与 `/settings`（含绑定）统一为设置区域，保留进入该区域前的实际路径；无来源回 `/me`。不把 `/me`、收藏、帖子等所有入口合并为一个区域，以免抹除真实父分支。恢复旧 v2 快照时移除末尾与当前区域相同的来源，但保留浏览器步数，从而兼容部署前已存在的设置子页记录。浏览器原生前进后退仍正常逐条访问，页面返回按钮跳出设置区域。

验证：324 项前端/插件测试与静态构建通过。新增设置分组、旧记录恢复、无历史入口与相邻分支回归；Chromium 用多文档跳转混合 pushState 设置标签与刷新，分别从 `/me`、`/me/bookmarks`、帖子进入，返回均准确回到各自来源。

## 统一个人中心工作区（2026-11-14）

用户澄清要求同级功能在一个外框内切换，不只是设置返回分组。个人侧栏现持续显示于 me 子路由、绑定、聊天及 Pulse；以用户/角色/语言键复用 DOM，站内菜单使用 History，后台和元衡站点继续独立。个人区域同级历史归组，返回跳出区域；勋章详情使用独立位置，先回列表。

新增私有壳层 /me/settings、/me/badges，/me/notifications 不再重定向；路由清单统一生成 Nginx 与两端 policy。内嵌视图仅映射已知 settings 四页、通知两页、勋章列表/详情，保留 Answer 原生表单、认证和保存接口，不复制账号数据模型或另建密码 API。原生页直接 URL 保留兼容。设置标签只更新父页 URL，勋章详情在父路由记录，出站内容在顶层打开。

原生 Answer 响应带 DENY，网关仅对上述页面去除上游 X-Frame-Options 并设置 SAMEORIGIN 与 frame-ancestors self，Cookie 白名单与伪造服务身份头清理和 no-store 保留。认证回调/后台/API 不加入白名单。不使用通用代理或任意 iframe URL，未知设置插件可在独立页面访问。旧静态更新但未部署网关时显示加载异常与原页面入口，不宣称已接通。

外框监听嵌入页表单修改，切换菜单/设置标签/返回/离开时提示未保存；只观察白名单 PUT 接口 HTTP 与业务 code 成功，不读取请求体或凭据；有新输入时旧保存回包不能清除脏状态。失败保持原表单。语言、头像等成功保存后重新读取当前用户刷新外框。视图销毁断开 ResizeObserver、监听与 XHR/history 包装。嵌入页图片高度和表单错误变化触发高度更新，避免双顶栏。

取舍：重写原生表单会重复认证、校验、插件和上传逻辑；普通整页链接无法实现用户确认的持续外框。选择有限同源嵌入，代价是依赖同源网关策略和双应用布局，需要一起部署前端与网关；非白名单新插件页保守独立打开。原生直接进入仍是原界面，不强制劫持所有公共 URL。

验证：映射/拒绝外站与 API、保存成功/失败/迟到回包、未保存取消、个人历史分组和原有路由回归通过。浏览器以完整构建与模拟账号接口验证未保存取消、500 保存失败保留、200 保存成功切换、设置同级标签与勋章详情、375px 无横向溢出；按拟部署响应头读取线上公开勋章页，原生内容正常、双顶栏消除。没有对真实账号写入设置。完整 Nginx 容器安全头与 Cookie 回归已增加，Windows 无 Docker 未运行，需 CI 验证；本地构建/资源检查通过。

最终验收补充：330 项前端/插件测试通过，8 项 Python 构建检查通过（Windows 跳过 POSIX umask 项）；浏览器确认 me→勋章列表→详情→返回列表期间父 document 和侧栏 DOM 为同一对象，再返回正确退出到来源 latest。
