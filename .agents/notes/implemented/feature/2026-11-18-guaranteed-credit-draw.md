# Agent Note: 有效券必得闪与附加经验

Status: implemented

## Problem

原闪与经验互斥奖池会使有效额度券只抽到经验。新规则需要一券必得闪，10% 加送经验，且不能改变旧券的原额度期限。

## Existing capabilities and impact

复用 [持续奖池](2026-11-17-scheduled-checkin-rewards.md)、已有券记录和 Answer 去重交付。扩展抽奖规则快照、奖励回执和后台预览，不改变每日签到闪或历史期限。

## Decision

发布新不可变规则快照。有效券在额度子池抽主奖，相对权重不变；由同一可重放随机种子域分离选择附加经验（触发率 10%，经验档位沿用）。额度到期券只参加经验子池，原票记录不变。附加经验写入同一发奖记录的独立交付状态，沿用论坛去重到账通道，和额度分别记预算，不创建第二个 Grant。

## Alternatives considered

重新提高额度资格会改写旧券合同；把经验留在主奖候选会继续出现只得经验；再写一条主奖 Grant 会破坏一抽一 Grant 的恢复语义。

## Consequences

额度有效券至少获得一份闪；到期券保留原经验权益。原推荐权重下闪的期望从 2.5 变为约 2.78，附加经验的期望仍为 0.57 EXP。预算不能覆盖全部可能结果时暂停抽奖，不缩减概率，不扣券。实际闪和附加经验分别到账及撤销；一次抽奖仍只记一份主发奖凭证。

## Verification

`draw_bonus_test.go` 覆盖双预算、10% 分布、过期分支、100 次重放、确认和撤销。`draw_bonus_mysql_test.go` 在隔离 MySQL 上使用正常仓储创建专用草稿周期、奖项与两类预算，再验证经验确认、撤销不改变闪的预留与交付。草稿夹具不替换其他集成测试的活动周期。票券统计的索引恢复场景只重放迁移 20 的 SQL，不改共享迁移记录，也不重放后续迁移。后台预览测试覆盖新权重分母及两类期望。

## 奖品卡即时结果一致性

即时结果此前只返回主奖字段，导致已有附加经验的奖品卡不展示经验；历史记录仍正常。对外结果保留已有脱敏字段，仅补入已确认的附加经验和状态。状态刷新只更新同一笔已确认奖品卡，不重新抽取或播放动画。通过模拟五连抽验证同金额的其他奖品不会错误带上经验。
