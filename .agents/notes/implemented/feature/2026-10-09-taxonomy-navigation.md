# Agent Note: 类别与标签进入讨论导航

Status: implemented

## Problem

已有类别目录使用大卡片，侧栏只有合并入口，讨论列表类别筛选另占一行。用户提供 Linux.do 截图，要求参考左侧类别/标签分组和列表顶部并排筛选，优先直接浏览内容。

## Decision

在 METAR 壳层增加可折叠的真实类别与常用标签分组，始终保留完整目录入口；讨论页将类别、标签和排序放在一条可换行工具栏，目录改用带简短介绍的紧凑行。继续使用现有推荐标签映射、单个原生标签筛选及原生发帖预选，不扩展数据库或创建假未读标记。顶部选择类别或标签会替换当前单一筛选，保留排序并回到第一页。

侧栏和筛选共用公开目录加载，按当前会话、语言和内容缓存代数隔离，在文档内短暂复用并合并并发请求；只保留类别及标签字段，不缓存完整站点设置或身份。数据加载不阻塞讨论正文，失败时保留目录入口。异步导航和身份切换不能把旧目录写入新页面。目录折叠状态仅保存在当前文档，保留窄屏抽屉和独立滚动。

## Alternatives considered

- 只改卡片尺寸：成本最低，但仍无法从讨论列表直接选择类别与标签，不能满足参考布局。
- 前端复制截图中的所有类别与未读蓝点：视觉接近但会虚构未启用类别及未读状态；使用 Answer 的真实数据和彩色类别标识。
- 新增双条件筛选 API：可以组合类别与标签，但 Answer 现有问题列表只接受单个标签，本次聚焦布局和现有查询能力，避免扩大后端范围。

## Verification

- `make test-community`：8 个 Python 构建测试、110 个前端测试、6 个 Answer 定制测试及 21 个插件测试通过。新增目录请求合并、会话/语言/代数隔离、失败重试、迟到响应、公开字段投影与未配置项目不生成链接的回归。
- `make build-community` 与博客构建、笔记校验通过。
- 本地正式构建搭配模拟内容验证类别/标签替换筛选、排序、分页复位、发帖预选、前进后退、刷新、侧栏高亮与折叠保留；85 个真实接口格式的模拟标签完整分页。
- 浏览器检查桌面、320px/390px、中英文及深浅主题。移动侧栏独立滚动，点击项目关闭抽屉；目录失败仍可读讨论；未初始化只显示预览及申请入口，不产生虚构可用栏目。
- 普通本地模拟账号与访客验收；未执行生产部署或生产账号验收。原生请求字段与 Answer 1.7.1 源码核对，初始化及申请 API 未改变。

## Consequences

侧栏提供直接切换入口，目录减少卡片留白，代价是完整类别列表需要独立滚动。折叠状态只在本次文档内保留，完整刷新恢复展开。原生单标签查询不支持同时组合类别和普通标签；两个选择器只会有一个当前筛选。常用标签不是完整目录，完整标签继续分页浏览。侧栏加载额外读取公开站点推荐标签、已存在的起步标签和首批热门标签，并只缓存名称投影 15 秒；不缓存完整站点设置、身份或权益数据。
