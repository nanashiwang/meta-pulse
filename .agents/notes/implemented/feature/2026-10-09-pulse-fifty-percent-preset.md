# Agent Note: 50% 额度概率与低经验奖池预设

Status: implemented

## Problem

用户确认 API 奖项 0.25/1/5/25 ⚡️、概率 44/5/0.8/0.2%，EXP 奖项 1/4/20、概率 28/12/10%。API 单券期望保持其提供的当前奖池基准 0.25 ⚡️，经验期望主动降低。现有预设仍是 10.6% 额度概率、0.05 ⚡️期望，且点击会同时覆盖产券门槛、有效期和预算模式，不能用于本次等期望切换。

## Decision

复用管理员不可变规则创建和用户规则查询，只更新可加载预设及概率/期望展示。API 奖项按当前 quota_per_unit 精确换成安全整数，经验保持原生整数；所有计算使用整数和 BigInt，预览按实际配置计算而不是写死 50%。用户以百分比读概率，同时保留权重供核对。到期券沿用 EXP 子池，概率 56/24/20%，期望 5.52 EXP；无需新增经验池。

载入预设只替换奖项和修改原因，不重置门槛、倍率、有效期、预算或发奖开关。已有规则编辑保留预算模式，但不预填一整份历史预算，新预算由管理员核对已发及预留后填写；页面明确当前快照不是自动周预算迁移。部署前后都不自动发布新经济规则。

## Existing capabilities and note review

复用 /admin/pulse、/pulse、admin-periods.js、adapters.js 与现有 BFF/API。已核验管理员角色及服务端整数配置边界。[统一规则笔记](../../implemented/feature/2026-10-09-pulse-current-reward-rule.md)部分重叠，保留其规则与重试机制；历史分组笔记的回执机制继续有效；动画/缓存等笔记无关。此预设不改变 API 契约、账本、预算和随机状态机。

## Alternatives considered

- 只把 API 权重提高：修改少，但原金额下提高概率增加单券成本，拒绝。
- 修改数据库或自动覆盖已启用奖项：立即生效，但破坏不可变规则及用户刚确认的旧操作，沿用审计创建路径。
- 保持 EXP 期望 20.4 并拆到期经验池：可守住旧经验期望，但用户已明确降低至 1/4/20，现有子池足够，避免增加规则分支。

## Verification

- 100000、500000 及边界换算比例下七档精确、权重合计 100000、API 期望 0.25、EXP 期望 2.76、到期 EXP 期望 5.52；安全整数边界、极小概率与非法输入回归通过。
- 实际生产壳浏览器验证加载预设保留倍率、门槛、期限和两个有限预算；保存响应丢失后刷新不写入，重试使用完全相同的内容与编号，服务端仅生成一份受控规则记录。
- `make test-community build-community`、`make build-blog`、发布脚本 10 项回归通过。真实旧奖池概率、编辑后清除旧预览、待确认请求保护经单元回归验证；中文/英文、390px/320px、暗色、未绑定及非管理员边界经浏览器验收。截图位于 `output/playwright/fifty-*.png`，使用本地受控数据，不代表生产配置或真实到账。

## Consequences

固定单券期望不保证固定周支出；每周预算 10000 ⚡️和旧库存消耗须独立管理。本次不添加统一周预算、不发每日券、不写生产配置、不部署生产。
