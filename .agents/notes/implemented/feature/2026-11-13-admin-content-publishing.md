# Agent Note: 管理员批量内容运营

Status: implemented

## Problem

管理员已有批量建号与账号切换，但缺少选择运营账号、批量话题/回复预览、逐条结果与重试审计。不得通过直接插入 Answer 内容表绕过权限与内容校验，也不能将运营代发伪装为真实用户自发互动。

## Existing capabilities and impact

复用原生 AddQuestion/AddAnswer、实时管理员身份和同源写保护。新建运营账号名单及发布项审计表，正文显式标注运营代发。现有账号切换与管理员免邮箱建号笔记部分重叠，保持原语义；不改变绑定和财务账本。

## Decision

提供 /admin/publishing，每批最多 20 项，可选择已登记运营账号并预览发布内容，支持话题和指定帖子下的回答。管理员会话保持不变，由受限服务端适配器以目标身份调用原生控制器，保持目标权限、审核和发帖规则；专用受控调用免交互验证码，公共接口不变。目标须正常、激活、非管理员且没有外部绑定。

每项使用不可变请求键，持久化后才调用发布器；返回不确定不自动重复发布。审计记录管理员、目标、内容、来源和结果，服务器补充显式代发标识。单项执行便于失败隔离和恢复，手工批处理由后台页面串行推进；JSON 关联与定时批次由[持久化调度扩展](2026-11-13-publishing-schedules.md)接管。

## Alternatives considered

- 浏览器循环切换登录：会污染当前会话并影响其他标签，失败恢复复杂。
- 直接写帖子数据库：绕过内容处理、标签、权限和审核，拒绝。
- 新建通用后台队列：能后台长批量执行，初版限制每批 20 项，使用单项审计和串行发布；定时需求已由后续持久化调度扩展接管。

## Verification

5 项前端发布回归和完整 226 项社区前端回归通过。Go 发布权限、校验、幂等与未知恢复测试通过（SQL 驱动夹具）；所有现有 Answer 补丁零 fuzz 叠加后，原生身份隔离测试和 router/controller 编译通过。本地浏览器模拟后台响应验证先预览零写入、确认后单次发布、结果链接及新建批次表单恢复。正式静态构建、路由生成和资源完整性检查通过。真实 MySQL 集成已加入 CI 8.0/8.4 矩阵，本机未配置专用数据库而跳过；没有在生产创建账号或发布内容。

## Consequences

代发内容仍遵循 Answer 权限及审核，不承诺全部即时上线。新增内容进入正常内容统计；仅无外部绑定运营账号可用，不授予额外资金权限。新表需备份；生产发布内容与部署单独授权。
