# Agent Note: 管理员从原生用户管理切换社区账号

Status: implemented

## Problem

Answer 1.7.1 已有用户管理、批量添加用户和管理员密码设置；本地账号模式允许这些入口。缺少管理员免密码切换与返回入口。其公开插件接口不提供原生会话签发服务，不能通过伪造浏览器 user_id 实现。

## Decision

复用 Answer 的 Connector 签发原生会话，新增独立的管理员切换 Connector 插件，由管理员显式启用；主插件提供受认证管理路由签发短期、一次性、绑定管理员当前凭据的交接票据。独立 provider 只映射现有本地账号，不操作 pulse_user_center 的 API 绑定、密码、角色或资金。用户列表补充切换按钮，双端提示当前切换状态并保留返回入口。

开始和消费交接都复查实时管理员和目标状态；拒绝自己、管理员目标、未激活/封禁/删除账号。交接和审计在 Answer MySQL 事务中，失败不返回凭据，不在 URL 中传票据。返回使用原来的管理员会话重新认证；原会话失效时要求重新登录。会话由 Answer 管理，切换后的操作具有目标账号的正常权限。

## Alternatives considered

- 直接使用原生添加用户：已满足创建需求，保持原生验证与批量表单；不能满足切换。
- 复制 Answer 缓存格式或修改密码：可快速实现登录，但依赖内部缓存和绕过凭据生命周期，拒绝。
- 修改 Answer 核心签发 API：最直接，但违背本仓库只维护插件、不 Fork 的边界。
- 独立 Connector：多一个启用开关和本地映射，代价明确，保留官方登录、注销及角色处理。

## Testing

MySQL 8.0 隔离测试覆盖普通用户拒绝、实时降权、非法/重复/过期票据、错误原会话、不可用目标、审计与映射、20 并发一次消费及频率限制。Node 回归覆盖切换/返回、失效原会话、禁用插件、存储失败、跨站回跳和迟到响应不覆盖其他登录。原生 Answer 1.7.1 容器实际验证管理员登录、原生创建用户、Connector 登录目标、返回认证、目标注销和原管理员身份保留。Playwright 测试页验证确认、返回和 390px 布局；完整 Forum 镜像、正式静态构建、Go 测试/vet、前端回归和笔记校验通过。生产尚未部署或启用插件。

## Consequences

正常 Answer 会话按原生期限存在，交接票据过期不等于注销。返回时需注销切换会话；不能承诺撤销已经在目标身份下完成的操作。不同窗口共享原生登录存储，身份变化时必须完整刷新避免旧页面误操作。旧浏览器页或丢失返回凭据可使用正常管理员登录恢复。

## Related notes

检索“用户管理、账号、身份、会话”：现有社区经营和任务赠券记录涉及身份复核，但没有登录签发决定；它们保持原边界，本记录只拥有切换能力。
