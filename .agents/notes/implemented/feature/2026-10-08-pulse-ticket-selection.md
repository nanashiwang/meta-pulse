# Agent Note: 按规则组选择券与固定拒绝回执

Status: implemented

## Problem

旧券的全局 FIFO 可在预算耗尽时阻断新券。规则预览和 Action 没有固定选择，响应丢失后的重试也不能证明用户原先确认的批次与资格。

## Decision

沿用发行批次、不可变规则、用户事务锁与双幂等记录。按规则 ID（预算归属）及混合/仅经验资格显示分组，在组内按获得时间及 ID 选择第一批券。服务端签发绑定本人、规则版本、批次及资格的选择凭据；v2 Action 将原凭据纳入指纹，事务内复核，状态变化要求重新确认。预览不预留券或预算，查询预算采用只读接口避免跨组持有预算写锁。实际提交在取得用户、券及预算锁后、首次金融写入前再次核对期限，排队跨期必须重新确认。

已提交操作先恢复原响应。明确无金融写入的业务拒绝以同一事务提交双幂等回执，再在事务外返回错误；数据库或提交错误仍为不确定结果。旧协议仅恢复已存在的结果，不创建没有原选择的新操作。五连抽固定同组同批次，当前批次不足五张时只开放单抽；不在中途切批次。

## Existing capabilities and note review

现有 `/pulse`、社区 BFF、规则查询、Action、预算、发行批次、sessionStorage 恢复均复用。既有动画笔记部分相关但决定不变：本次只扩展操作身份，保留揭晓语义。loading-shell 与本次经济契约无重叠，无需修改。管理员预算展示复用既有管理入口。

## Alternatives considered

- 失败后自动跳过旧券：交互简单，但会改变用户确认的规则与奖项范围，拒绝。
- 仅传规则 ID：能够隔离预算，却不能固定跨期限和并发耗尽时的批次，拒绝。
- 单独保存选择预留表：可以预留整轮券，但引入预留释放、期限和额外事实源；本次使用可重验证的 HMAC 凭据，不预留。

## Consequences

升级必须排空旧 API 写请求，旧前端只能恢复原请求。签名使用随机根密钥加独立用途前缀，不新增角色密钥复用；未提交凭据在密钥变化后需重新确认，已提交回放不依赖现密钥。日券、门槛、概率、经验成长和生产配置不属于此次变更。
