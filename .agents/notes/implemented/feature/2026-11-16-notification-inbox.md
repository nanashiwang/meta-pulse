# Agent Note: 通知分类与评论预览

Status: implemented

## Problem

个人中心收件箱把评论、点赞及其他内容变动混排，用户无法快速查看评论正文。现有原生筛选子路径也不属于个人中心同源白名单，切换会离开外框。

## Decision

使用全部、评论、点赞三个入口，复用原生通知接口，服务端以存储的原始事件在分页前筛选；保留用户归属和通知类型条件。评论包括评论、回复及评论提及，点赞只包含upvote，其他事件留在全部。旧posts/votes/invites接口兼容保留。

使用原生inbox页面的filter查询参数，双向映射到个人中心同名查询；不扩大可内嵌路径白名单。按路径与查询重新挂载原生通知组件，避免切换时分页或旧列表混入。

评论预览在翻译与短ID转换前读取当前评论，确认评论、父回答、父问题状态及问题显示状态。渲染文本前去除HTML，合并空白，按Unicode码点截取25字后追加省略号。缺失或不可见内容不返回预览；点击保留原评论定位和已读操作。

## Alternatives considered

仅在浏览器隐藏已加载通知无法正确计算总数及后续分页。保存通知时复制评论正文会在删除或隐藏后残留内容，因此选择读取当前可见正文。重写独立通知页会重复认证、未读和内容跳转行为，故保留原生组件并通过构建补丁扩展。

## Consequences

无需数据库迁移，兼容历史通知。新增分类依赖Answer以JSON序列化存储的固定事件键；每页评论预览最多增加每条三次小查询，优先保证父内容状态校验，后续可在保持权限语义下批量优化。完整上线需同时更新forum镜像与社区静态资源，不能只更新静态前端。

## Verification

真实SQLite回归验证分页前分类、总数、账号隔离和稳定分页；预览回归覆盖中文、emoji、25字边界、HTML、空白以及删除/待审评论、隐藏/待审问题和删除回答。个人中心路由回归覆盖筛选往返和非法参数拒绝。详细执行结果以本次验收记录为准。
