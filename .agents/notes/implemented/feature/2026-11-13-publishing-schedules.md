# Agent Note: 内容运营定时讨论导入

Status: implemented

## Problem

现有内容运营已支持多账号话题及回答，但需要手工填写帖子编号，浏览器退出即停止批处理，缺少评论和定时依赖。

## Decision

复用专用运营账号、原生发布适配器和单项幂等审计；新增 Answer 库持久化批次与进度，由论坛进程轮询。JSON 使用 id、parent、publish_at 表达依赖，父项必须在前；comment 映射 Answer 评论和 reply_comment_id。继续显式标注运营代发。执行时重查管理员及目标权限，未知结果暂停该批，支持取消未执行项。

与[现有内容运营](2026-11-13-admin-content-publishing.md)部分重叠，其单项发布决定仍成立；JSON 后台队列取代仅浏览器串行这一范围。

## Alternatives considered

- 浏览器定时器：复用简单，但关页、休眠后不能履约。
- Pulse Worker：已有调度，但需要跨服务携带论坛身份和原生发布能力，扩大边界。
- Answer 进程持久化队列：增加状态和轮询维护成本，但保留社区身份及内容事实在同一服务。

## Verification

JSON 时间/依赖/评论限制与前端导入预览回归通过；Go 发布测试及全插件 race 测试通过。隔离 MySQL 8.0 验证批次重复提交/内容冲突、8 个并发执行器、未来任务等待、父子结果、取消剩余项、丢响应后显式核对继续无重复发布。原生 Answer 全补丁叠加及 router/controller 编译通过；正式社区静态构建通过。浏览器连接超时，没有宣称完成真实页面验收。

## Consequences

持久化批次随 Answer 备份；保留原生权限、审核及公开运营代发标识。任意权限或未知结果暂停本批，人工继续沿用原键；原生返回失败且查无内容时不会自动重新创建，可能需要人工处理。每批最多 20 项，保留每管理员每分钟 20 个新项限制。定时表示不早于指定时刻，不承诺精确秒级上线，停机后补执行；管理权限撤销后任务暂停。生产部署、真实内容与账号上线验收单独进行。
