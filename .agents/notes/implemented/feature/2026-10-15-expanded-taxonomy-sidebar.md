# Agent Note: 默认展开侧栏类别与标签

Status: implemented

## Problem

侧栏收紧并增加成员入口后，用户希望利用剩余空间，像参考图一样直接看到类别和标签，减少先打开面板再选择的步骤。

## Decision

默认展开两个真实目录分组，允许折叠并在当前文档内保留状态。复用 Answer 推荐标签、已存在常用标签和热门标签的公开投影及请求合并；不写站点数据、不生成假未读点。类别预览最多 16 项，标签 8 项，已加载目录中超出预览的当前选中项补充展示；完整目录和搜索面板始终可达。侧栏独立滚动，手机选择项目后关闭整体抽屉。首屏显示展开骨架，不用起步示例冒充实时数据。

## Existing-note audit

[按需面板](../../implemented/feature/2026-10-09-taxonomy-drawer-names.md)的默认展示决定被本次用户要求替代，原命名与管理员同步规则保留。[早期目录导航](../../implemented/feature/2026-10-09-taxonomy-navigation.md)的数据来源、缓存、单条件筛选和文档内折叠规则继续复用。[侧栏开关](../../implemented/feature/2026-10-15-sidebar-toggle.md)继续控制整个左栏，不与分组折叠共用状态。

## Alternatives considered

- 只保留当前按需面板：代码无需变化，但不满足直接展示目录的目标。
- 将全部热门标签放进侧栏：少一次跳转，但大型目录会挤占其他导航且并非完整标签全集。采用有界预览并保留完整目录。
- 删除搜索面板：可以减少代码，但失去快速检索已加载目录的能力；保留为每组的搜索入口。

## Verification

8 项 Python 构建检查、124 项前端测试、6 项社区定制及 27 项插件测试通过。浏览器在正式壳和隔离目录夹具中验证默认展开、选中项、完整目录高亮、折叠跨切页/语言保持、刷新恢复展开、整体侧栏开关、搜索、非讨论页加载、390px 独立滚动与选择关闭、深浅主题、读取失败及重试；阻塞主脚本时对首屏分组的折叠在启动后保留。

## Consequences

类别与标签较多时需要滚动左栏。预览不是完整标签目录；入口明确保留完整目录。改变历史默认展示只影响前端，不改标签名称、关联和奖励资格。
