# Agent Note: Vibe Coding 集市产品提案

Status: proposed

## Problem

成员需要发现与体验 AI 辅助开发作品，并将想法讨论关联到后续项目。当前普通类别列表无法表达用途、体验方式、费用和源码。本轮用户授权产品设计，尚未授权业务实现或部署。

## Existing capabilities and impact

已核对 [taxonomy.js](../../../../metar-frontend/production/src/taxonomy.js) 与[共享路由](../../../../metar-frontend/shared/routes.json)：类别来自 Answer 推荐标签，尚无集市路由。复用 Answer 身份、内容、评论、收藏、草稿与治理；新增结构化项目展示。影响桌面/手机/原生导航、类别目录、搜索、发布编辑、详情与审核。

检索活跃笔记 `集市|marketplace|vibe|项目展示|站内运行` 未发现既有决定；补查类别与任务边界：[类别治理](../../implemented/feature/2026-10-09-community-taxonomy.md)和[展开侧栏](../../implemented/feature/2026-10-15-expanded-taxonomy-sidebar.md)部分重叠，沿用身份、分类事实和共享入口；[社区赠券](../../implemented/feature/2026-11-06-community-tickets.md)仅边界相关，保留原任务口径，不新增经济奖励。没有被本提案完整取代的笔记。

## Proposal

完整设计见[产品方案](../../../../docs/VIBE_CODING_MARKETPLACE.md)。左侧类别新增同名入口，集市分项目和想法讨论，默认项目卡片；想法可关联多个实现，保留原讨论和作者关系。推荐标签继续承载内容归属，项目元数据拟由 Answer 插件维护，正文和互动仍归 Answer。

首版收录 GitHub 与作者部署的 HTTPS 演示，允许嵌入且审核后才站内体验；不能嵌入则外站打开。站内体验不等于平台托管源码，不传论坛会话/Key，不隐式使用访客元衡余额。平台托管、统一调用和交易另行立项，模型请求不经 Pulse。

项目提交、收藏、浏览、运行和需求支持不产生新贡献或赠券渠道；原生讨论符合原规则时仅计一次。首次发布及运行地址/归属变更人工审核，已发布版本不被待审核地址覆盖。正式实施前验证 Answer 编辑扩展点、发布一致性和原生入口不能绕过审核。

本轮仅新增方案与对话原型，能力地图明确列为未实现提案；不修改运行系统架构事实。

## Alternatives considered

- 只增加普通类别和发帖模板：成本最低，可迅速试运营；但演示与费用埋在正文中，难以集中发现，保留为极简试运营选项。
- 独立应用市场：项目模型可完全自由设计，但重复社区身份和治理，割裂互动；优先专属展示加 Answer 扩展。
- 首版直接托管代码：体验统一，但需要构建、隔离运行、持续预算与运维；先收录已有应用，再以真实需求判断是否立项。

## Acceptance criteria

- 当前产品交付：完整设计、可交互示例与明确未实现标记；笔记结构和原型交互校验通过。
- 后续业务交付：双端及原生导航一致，GitHub-only/演示-only/混合/失效状态可用，费用事前可见，身份/审核服务端检查，丢响应和重复提交可恢复。
- 想法关联作品保留讨论与作者，项目地址变更重新审核；原生编辑不得绕过。
- 体验隔离不泄露凭证，失败可外站打开且不阻断浏览；真实浏览器验证不能由本地示例替代。
- 实施时更新架构、社区说明、共享路由与相关回归，生产验收单独完成。

## Risks

“网站调用”也可能指运行源码；本提案按嵌入作者应用设计，若要求平台托管需重新评估资源边界。公开仓库不必然开源或归投稿者所有，需保留许可证和作者关系。演示失效与内容审核增加运营成本；插件扩展点尚需工程验证。本轮原型使用示例数据，不调用模型或写生产类别。
