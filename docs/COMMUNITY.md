# Meta Pulse 社区｜论坛、博客与账号绑定架构

本文档定义社区层边界。`docs/ARCHITECTURE.md` 仍是系统基线。

管理员头像菜单的「社区经营」展示注册、访问/有效活跃、自然日 D1/D7/D30 留存、注册后七个中国法定工作日（含调休）的活跃人数与天数分布、访客注册转化耗时、内容供给和回应情况，并支持管理员私有运营标签。时间窗口、样本和历史缺口必须一起阅读，具体定义与后续指标建议见[社区经营口径](COMMUNITY_ANALYTICS.md)。统计不改变内容治理、经验、抽奖或资金事实。

Pulse 管理页直接配置长期生效的新券额度资格天数、奖项权重和预算，不再向运营或用户暴露周期切换。社区账号必须处于活跃状态并完成保护绑定；仅下述限额社区任务获得新脉冲券，API 消费不再获券，历史已发券继续可用；社区抽奖页展示券余额、原额度期限与抽奖入口，奖励记录通过右上角小字入口打开，用户端不展示奖池概率，到期券仅抽最新经验奖项。管理身份仍来自 Answer 实时复核，普通用户身份仍来自受保护绑定；额度与 EXP 的事实源和交付边界不变。详见 [管理设置](METAR_ADMIN_SETTINGS.md)。

## 1. 产品定位

对外入口采用“**社区为主，Pulse 权益为辅**”：

- Apache Answer：注册、登录、问答、资料、封禁与社区关系；
- VitePress：教程、评测和搜索引流；
- Meta Pulse：社区任务赠券、抽奖奖励和内容权益；
- new-api：API 登录、模型调用、计费、充值和余额。

社区账号无需 new-api 即可注册和使用；绑定 new-api 只用于解锁 Pulse 社区任务与抽奖权益，不改变 Pulse 的经济事实源。

## 2. 服务、数据库与事实源

```text
Answer   = 社区身份、密码、会话、封禁、资料、内容事实源
new-api  = API 身份、模型调用、计费与资金事实源
绑定关系 = Answer user_external_login 中 provider=pulse_user_center 的记录
Pulse    = Ticket / Reward / Budget / Rule Snapshot 事实源
```

| 数据库 | 归属 | Pulse 权限 |
|---|---|---|
| new-api LOG_DB | new-api | 无需连接；消费贡献已退役 |
| `meta_pulse` | Pulse | 读写 |
| `meta_pulse_forum` | Answer | 内容采集账号只读 |

论坛插件使用 Answer 数据库账号安装并检查绑定约束，但该 DSN 只注入 `forum` 容器，不进入 Pulse API/Worker。服务、数据库、账号和更新流程保持独立。

## 3. Apache Answer 选型

使用 Apache Answer v1.7.1：Go/Gin/MySQL/React 技术栈一致，具备 SSR/站点地图、多语言、Connector 与 UserCenter 扩展点。

不 Fork Answer。仓库只维护：

```text
services/forum/                         Answer 构建定义
services/forum-plugin/user-center-pulse Connector + Pulse 徽章插件
```

Go 无动态插件机制，因此 Answer 升级后必须重新编译并做真实 schema、登录、绑定、资料和封禁回归。v2 当前模块路径兼容问题未解决前不升级。

头像使用 Answer 官方外观扩展：默认设为系统头像，并安装 [`avatar-head.html`](../services/forum/customization/avatar-head.html)，将默认/失败头像显示为本地生成的用户名首字符。用户仍通过 Answer「编辑资料 → 头像 → 自定义」上传更换；不会修改头像数据库字段或关闭外部媒体保护。安装、升级与回退见[头像定制说明](../services/forum/customization/README.md)。METAR 静态首页同样支持同源上传头像和首字符回退。

启用 UserCenter 插件并重建 forum 后，资料页自定义头像先在浏览器裁剪：选择 JPEG/PNG/WebP → 拖动与 1–4 倍缩放 → 圆形预览 → 确认。输出为 512×512、白底 JPEG，逐级压缩至不超过 200 KiB，再交回 Answer 原生上传；上传后仍需点击“保存资料”才更新账号。原图上限 20 MiB，解码后上限 4000 万像素；HEIC 等格式明确拒绝。取消或离开资料页不上传，其他图片上传入口不受影响。实现位于 [avatar-cropper.js](../services/forum-plugin/user-center-pulse/avatar-cropper.js)，随插件 Go embed 打包，无额外上游补丁。依赖原生 dialog、createImageBitmap、DataTransfer；Answer 升级需回归资料表单 `select[name="avatar.type"]` 与原始文件 change 上传链路。Node 回归验证事件交接，不替代真实浏览器上传和保存验收。

### 3.1 中英文界面

原生论坛和 METAR 静态首页右上角均提供「中文 / English」。用户显式选择后，偏好保存在同源浏览器的 `metar-language`（`zh_CN` / `en_US`），刷新、切换页面、登录或退出后保留；浏览器存储禁用时当页仍可切换。静态首页默认中文，原生论坛未显式选择前沿用 Answer 账号/站点默认语言。该偏好只控制界面，帖子正文、标题、用户名和用户资料保持原文。

原生入口随现有 `pulse_user_center` 插件的 UI 模块构建，插件须启用；使用 Answer 自身的 i18next、官方中英文字典和日期库，不 Fork Answer。模块仅将用户显式选择映射到 Answer 内存中的 `user.language`，让原生界面和 API 提示一致；不写用户资料、会话或站点默认设置，不请求 new-api/Pulse。浏览器偏好优先于账号语言；用户可用右上角控件切换，其他设备不受影响。

UI 资源通过 Go embed 保留到 `go mod vendor`，官方 `answer build` 负责复制私有插件、加载与打包。更新需重建 `forum` 镜像（普通 `metar update` 即可，勿用 `--skip-forum`），无需额外粘贴外观脚本。Answer 升级时需回归 `@/i18n/init`、`loggedUserInfoStore`、`#header > .w-100`、访客/登录用户、语言异步初始化竞争及手机导航布局。

### 3.2 普通路径与列表首页

新旧页面共享 `metar-frontend/shared/routes.json` 的路由归属。Answer 插件会在导航到 METAR 页面后完整切换页面，避免点站名或登录回跳后仍停留在旧首页；编辑器阻止的导航不会触发切换。增加页面时运行 `python3 metar-frontend/shared/generate-routes.py` 同步两端策略和网关，再运行 `make test-community`。

首页 `/` 与 `/latest` 共用 METAR 讨论列表，筛选和分页复用 Answer API。精确 `/questions` 和 `/discover` 加载同一壳层后规范到 `/latest`，保留查询和 Hash。`/topics` 是类别目录，`/topics?view=tags` 分页显示全部原生标签；`/topic/:slug` 是类别或标签下的讨论，`/question/:id` 是问题只读详情。类别筛选在讨论内容显示后加载，切换类别保留排序、重置分页，新建话题预选当前类别或标签。手机端收拢次要指标，保留标题、标签、回复和活动时间；中英文与深色主题沿用浏览器偏好。

社区自有页面直接从内容或操作区开始，移除外层面包屑、大标题与宣传介绍。讨论页在类别、标签及排序栏上方居中展示搜索框，并紧接社区准则提示与链接；不再展示元衡 API 推广行，顶部移除开发者外链。类别、标签选择器与排序并排，搜索数量位于输入框下方，完整知识库入口保留在内容区；页面名称继续提供无障碍语义。个人资料、正文标题、绑定确认、身份与错误提示正常展示。知识库首页同样收紧宣传区，保留分类按钮和卡片，文章标题不受影响。初始加载骨架采用相同的紧凑布局。

旧 `/#/...` 分享链接由前端转换，刷新与直接访问由 Nginx 白名单处理。原生 Answer 的发帖、问题互动、账号、通知及所有 API/回调路径继续保留；收藏与通知壳层分别使用 `/me/bookmarks` 和 `/me/notifications`。完整边界见架构第 44 节。

### 3.3 统一视觉与主题

站点 Logo 使用用户提供的蓝色渐变原图，主页页头、加载占位、原生论坛页头和知识库标题共用同源图片，深浅主题均保留原图白底。首页和博客显式引用由原图生成的自包含 SVG 图标；Answer 未填写品牌图标时使用的 `/favicon.ico` 由网关提供真实多尺寸 ICO，同时覆盖帖子、标签、账号页及默认 manifest。Answer 后台已指定的其他图标 URL 保留。Forum、静态资源与网关需一起部署，既有浏览器图标缓存需重新打开标签验收；原稿与导出说明见[正式前端说明](../metar-frontend/production/README.md)。

所有 METAR 静态入口的初始 HTML 提供完整匿名页面骨架，包含页头、侧栏、内容区域与移动导航；慢脚本不会只留下标题说明。列表、标签/知识库和一般面板采用共用模板的不同布局，保留中英文和主题偏好、脚本失败的恢复入口及无脚本公开内容。浏览器恢复同一公开页面时保留当前内容和滚动位置，后台更新失败会明确提示。相同语言和会话内切换最新、热门、分页或类别/标签时，保留上一份讨论列表及其筛选高亮，待新数据成功后一起切换；慢请求延迟显示轻量提示，失败保留旧列表并提供重试，旧响应不能覆盖后续选择。身份、语言变化及私人/权益页面仍重新加载和校验；401/403 拒绝会清除旧视图。

`metar-frontend/shared/theme-tokens.css` 是社区、原生 Answer 与知识库的共用配色。`theme-core.js` 管理浏览器主题，修改后运行 `python3 metar-frontend/shared/generate-theme.py` 打包到静态前端和 Go embed 插件；测试检查产物没有漂移。

三个界面共用 `_metar_theme`（`light` / `dark`），显式选择后保持到刷新、跨页面与同源其他标签；未选择时跟随系统，存储禁用时当页仍可用。VitePress 的 `auto` 值按跟随系统处理。该偏好只影响此浏览器，不写账号或站点配置；文章语言仍由内容本身决定。Answer 的异步站点/账号默认主题不能覆盖浏览器当前选择。

启用 `pulse_user_center` 插件后，原生页面使用 METAR 页头、导航和样式。新增导航采用普通链接，保留浏览器及 Answer 的离开页面保护；非编辑页面的站名和后台“返回网站”直接使用 `/latest` 的浏览器文档导航，保留 Answer 的 `beforeunload` 草稿提醒，避免先渲染旧首页再跳一次。其他原生 React 导航仍经过第 3.2 节的提交后切换。菜单和表单的权限、校验、验证码、上传、草稿、保存仍由 Answer 提供。插件关闭时 Answer 可以继续独立工作，但统一外观与导航桥不再加载。

升级 Answer/VitePress 时需回归页头结构、原生主题异步初始化、个人页和编辑器、管理侧栏、320px/390px 窄屏、英文长标签，以及知识库首屏主题脚本。完整进度见 `METAR_UNIFICATION.md`。

### 3.4 类别、标签与新增申请

类别复用 Answer 的管理员推荐标签，普通成员仍能在原生编辑器选择；其他标签继续用于交叉标记。起步集合保留现有链接标识，名称使用 METAR 自身表达：开发实践、国产生态、工具资源、资料分享、教程共建、招聘协作、阅读思考、科技动态、好文收藏、优惠活动、日常交流、灵感交流、站务建议。常用标签为 AI 交流、社区公告、原创分享、问题求助、有奖活动、精选内容、专题汇总。

METAR 左侧默认展开真实类别与常用标签，点击项目直接筛选讨论。类别预览最多 16 项、标签 8 项，已加载目录中的当前选中项即使在预览之外也会补充显示。分组可折叠并在当前文档内保留状态，刷新恢复展开；每组保留完整目录链接和搜索面板。侧栏独立滚动，手机选择项目后关闭整体抽屉。目录仍只读取当前推荐类别、已存在的起步标签与首批热门标签，不用示例冒充已启用项目。公开目录名称按会话、语言和内容缓存代数隔离，当前文档短时复用；加载或失败不阻塞讨论正文，失败可重试。搜索面板和顶部单标签筛选保持原语义。

升级不自动写入站点数据。部署后，已激活管理员通过头像菜单「类别管理」进入 `/admin/taxonomy`，核对目录后执行「同步类别与标签」。先补齐缺失标签、合并推荐标签并验证设置，再将相同 slug 下与旧版默认名称完全匹配的标签更名为新名称；管理员自定义名称不会被覆盖。更新使用 Answer 原生标签编辑，保留 ID、slug、介绍原文与帖子关联，记录编辑摘要，并逐项读回核实。原生推荐标签会随标签记录返回新名称，避免前端、帖子和编辑器分别维护名字。重复同步先读现状，不重复改名；未知写入结果或验证失败先停止，保留已完成部分。

同步保留其他推荐/保留标签和撰写设置。原生 API 没有原子版本锁，同步期间避免其他管理员同时编辑标签及撰写设置；同名标签被删除、属于同义词、原文响应不完整，或起步类别与保留标签冲突时，先在原生管理中处理后重试。

目录顶部提供「申请新类别」「申请新标签」「查看站务建议」简洁入口。模板引导用户说明建议名称、用途、现有目录不足和示例；进入 Answer 原生编辑器后发布才算提交，默认选择已经存在的 `feedback` 标签（新名称「站务建议」）。登录、激活、验证码、草稿和发布校验由 Answer 负责；管理员在原帖回复结果，通过后创建标签，新增类别再加入推荐标签。普通用户自建标签不会自动成为类别，社区公告等管理专用标签仍可由管理员设为保留标签。

Answer 允许多个推荐标签，不强制单一类别；资料分享独立筛选，不自动合并到工具资源。申请、标签及「有奖活动」不授予 Pulse 权益，不改变内容奖励资格。

发帖与问题编辑页将原生「类别与标签」选择区放在标题上方。类别继续作为推荐标签优先选择，普通标签仍在同一输入框搜索添加；选择、删除、最多五项、权限、校验与草稿均沿用 Answer。菜单按窗口和手机键盘留下的可视空间限高，空间不足时向上展开并在列表内部滚动。

## 4. 双身份与可选绑定

管理员创建与切换社区账号复用 Answer 原生用户管理和官方登录机制。切换入口、独立插件启用、返回管理员与审计见[社区账号管理](ACCOUNT_MANAGEMENT.md)，不会修改 new-api 绑定。

### 4.1 账号原则

- Answer 开启本地注册、密码登录、资料维护和本地封禁；
- new-api 账号与 Answer 账号可以分别存在；
- 绑定是可选操作，不绑定也能浏览、注册、登录和发帖；
- 一个 Answer 用户最多绑定一个 new-api 用户；
- 一个 new-api 用户最多绑定一个 Answer 用户；
- 禁止静默换绑、身份转移和普通自助解绑；
- 纠错只能在备份后进入维护窗口，由授权管理员执行并留下工单、操作者、原因、前后值和时间审计。
- 社区网页登录凭证默认保持 30 天；有效访问会同时刷新 Answer 服务端会话缓存和 `visit` Cookie，因此是滑动 30 天窗口。主动退出、服务端撤销、账号状态失效和 Answer 会话缓存丢失仍会立即终止会话。

Answer 的 `user_external_login` 是绑定事实源。插件为 `provider = 'pulse_user_center'` 增加条件生成列、单列唯一索引以及 INSERT/UPDATE/DELETE 触发器：

```text
new-api external_id  一对一  Answer user_id
```

插件启用和每次可信 callback 前都检查约束是否完整；缺列、缺索引、复合索引冒充、缺触发器或数据库不可用时绑定 fail closed。其他 Connector 不受这些条件约束影响。

### 4.2 为什么不按邮箱自动绑定

new-api 现有 Login Ticket 包含邮箱，但没有证明历史邮箱一定已经验证。Connector 因此向 Answer 返回空 Email/Avatar：

- 不按同名邮箱静默接管已有社区账号；
- 新绑定沿用 Answer 自带的邮箱确认流程；
- 社区昵称、头像和资料仍由 Answer 管理。

### 4.3 本地封禁权

插件配置：

```text
EnabledOriginalUserSystem = true
UserStatusAgentEnabled    = false
RankAgentEnabled          = false
```

new-api 或 Pulse 不覆盖 Answer 的封禁、密码、资料和治理角色。Pulse 等级只能展示，不能兑换社区管理权限。Pulse 不可用时徽章降级为空，不阻断 Answer 本地登录或浏览。

## 5. 绑定与登录链路

可选账号绑定复用 new-api 已有 SSO Bridge；该绑定流程本身不要求修改 new-api 业务源码。自动抽奖另需升级付费来源证明与 Benefit 接收端，见第 12 节。原站 Nginx 增加固定的同源 bootstrap 页面，解决其 `SameSite=Strict` session Cookie 在 metarhub.com 跨站跳转时不发送的问题：

```nginx
location = /api/forum/sso/bootstrap {
    default_type text/html;
    add_header Cache-Control "no-store" always;
    add_header Referrer-Policy "no-referrer" always;
    add_header X-Content-Type-Options nosniff always;
    add_header X-Frame-Options DENY always;
    add_header Content-Security-Policy "default-src 'none'; base-uri 'none'; frame-ancestors 'none'" always;
    return 200 '<!doctype html><meta charset="utf-8"><meta http-equiv="refresh" content="0;url=/api/forum/sso/start"><a href="/api/forum/sso/start">继续</a>';
}
```

该页面只在 new-api 域名下提交一次文档，再导航到固定 SSO 路径；不接收用户输入、不携带凭据、不构造开放重定向。


```text
Answer Connector 入口
  → 写入短期 HttpOnly/Secure/SameSite=Lax 浏览器 flow
  → new-api 同源 SSO bootstrap 页面
  → 同源 GET /api/forum/sso/start（携带现有 new-api session）
  → new-api 从自己的 session 派生用户并签发短期 Login Ticket
  → 302 到社区固定 callback
  → Nginx rewrite 到 Answer Connector receiver
  → 严格解析、验签、检查 Binding Guard
  → Redis 原子消费 flow + ticket nonce
  → Answer 已绑定用户直接登录；未绑定用户走邮箱确认后创建/绑定本地账号
```

仅开通可选账号绑定时，new-api 增加以下配置并重建其容器：

```env
PULSE_FORUM_SSO_SECRET=<与 Answer 插件 sso_hmac_secret 一致>
PULSE_FORUM_SSO_CALLBACK_URL=https://metarhub.com/api/user-center/login/callback
```

new-api 继续在原服务器独立运行。以上是 SSO 绑定的配置要求，不包含自动奖励所需的钱包核算迁移、接收端升级和额度上限。

### 5.1 Answer v1.7.1 跳转适配

插件同时实现 Connector（安全绑定）和 UserCenter（Pulse 徽章展示）。Answer v1.7.1 只要检测到 UserCenter，就会在登录页展示 UserCenter 按钮，并把全站注册链接指向框架跳转端点；其 sign-up handler 还错误读取 `LoginRedirectURL`。如果插件把这两个地址留空，浏览器会落到不存在的 `/answer/api/v1/user-center/login/` 或 `/sign-up/`。

为保持“双身份、可选绑定”：

- 插件声明 UserCenter 登录目标为 `/answer/api/v1/connector/login/pulse_user_center`；
- 插件声明注册目标为 Answer 本地 `/users/register`；
- 公网 Nginx 对 `/answer/api/v1/user-center/agent` 的公开 JSON 响应做定点归一化：`login_redirect_url` 使用相对 Connector 路径，`sign_up_redirect_url` 必须保持字面值 `/users/register`，使 Answer 前端不再重定向本地注册页；代理关闭上游压缩与缓存，且仍执行 Cookie、身份头隔离；
- 网关把框架 `/login/redirect`、`/sign-up/redirect` 以及已生成的 `/login/`、`/sign-up/` 旧链接作为兼容兜底，分别送往 Connector 和本地注册；
- 登录入口不得直接跳到 new-api `/api/forum/sso/start`，必须先经过 `/api/forum/sso/bootstrap`，否则浏览器可能因 `SameSite=Strict` 不发送已有 new-api session。

该适配只修复 Answer 框架跳转，不改变社区账号、密码、封禁和资料仍由 Answer 管理的事实源。

### 5.2 Login Ticket

```text
payload   = user_id \n username \n display_name \n email \n avatar \n timestamp \n nonce
signature = hex(HMAC-SHA256(PULSE_FORUM_SSO_SECRET, payload))
```

接收端必须：

1. 只接受 GET，限制 query 总长度；
2. 要求八个字段各出现一次，拒绝缺失、重复和额外字段；
3. 拒绝 CR/LF、非规范正整数 `user_id`/`timestamp`、过期和过早 Ticket；
4. 使用常量时间 HMAC 校验；
5. Binding Guard 正常后，才原子消费浏览器 flow 与 Ticket nonce；
6. Redis 不可用、约束不完整或状态不确定时失败，不降级为放行。

SSO 密钥与 Pulse 只读 Profile、Settlement/Worker 服务签名密钥分离且禁止复用；轮换期只允许“当前密钥 + 明确配置的上一密钥”。

### 5.3 已知剩余限制

现有 new-api Ticket 没有签名 `state`。当前浏览器 flow marker 能拒绝未从社区发起的 callback，并防止 flow/nonce 重放，但**不等价于 OAuth 的完整 signed state**。

当前 SSO Ticket 契约仍保留该限制；自动奖励升级没有修改此契约。短有效期、固定 callback、HttpOnly flow、单次 nonce、Answer 邮箱确认和不可转移绑定共同收敛风险。后续 SSO 专项升级仍需将高熵 `state` 写入 Ticket 签名并在 callback 等值校验。

## 6. 网关与 Cookie 边界

社区使用独立产品域名：

```text
https://metarhub.com/       METAR 静态首页；其他社区原生/API 路径由 Answer 提供
https://metarhub.com/blog/  VitePress
https://www.metarhub.com/   跳转主域名
```

new-api 继续运行在其现有域名和服务器。社区 Nginx：

- 不代理 new-api 或 Pulse；
- 普通请求只向 Answer 转发 `visit` Cookie；
- callback 只转发短期 flow Cookie；
- callback 清除 Authorization；普通请求保留 Answer 自己的 Authorization，否则本地登录后的 API 会失效；全部路由清除 Pulse 签名头；
- HTTP/HTTPS access log 使用不含 query 与 Referer 的专用格式；callback、`auth-landing`、`confirm-email` 额外关闭 access log，并返回 `Cache-Control: no-store` 与 `Referrer-Policy: no-referrer`；
- Answer/Pulse/MySQL/Redis 容器不直接发布宿主机端口。

这保证社区故障不会进入 new-api 模型调用、计费或充值主链路，也不会把 new-api session Cookie 交给 Answer。

## 7. Pulse 等级与权益解锁

仅绑定用户可以通过稳定的 new-api `user_id` 查询 Pulse 等级。论坛插件以 `forum` 服务角色和独立 `PULSE_FORUM_HMAC_SECRET` 调用 Pulse 只读 Profile 接口；该密钥不得与 Settlement/Worker 的 `PULSE_SERVICE_HMAC_SECRET` 或 Forum SSO 的 `PULSE_FORUM_SSO_SECRET` 复用，插件配置会拒绝复用。浏览器不能声明身份。

```text
Answer external binding
  → new-api user_id
  → Pulse GET /v1/internal/users/:user_id/profile
  → PersonalBranding 展示等级/贡献值
```

Pulse 失败时返回“无徽章”，Answer 的本地账号、会话和内容仍正常。

## 8. 内容奖励

论坛内容永远不产生 contribution 或 ticket。内容奖励是独立、人工审核、可撤销的 Reward Grant：

```text
Answer 只读公开问题元数据
  → Content Candidate
  → 保护绑定 + 人工审核 + 双层限额 + Hard Budget
  → Reward Grant / Outbox
  → new-api Benefit（transferable_quota=false）
```

采集边界：

- 只读 Answer v1.7.1 `question` 与受保护的 `user_external_login`；
- 只采集 `show = 1` 且 `status IN (available, closed)` 的问题；
- Answer 本地 `user_id` 不能直接当作 new-api `user_id`；
- 只采集绑定存在且 `binding.created_at < question.created_at` 的内容；Answer 时间戳为秒级，同秒无法证明先绑定后发布，因此 fail closed；
- 未绑定用户、绑定前/同秒内容、隐藏/待审核/删除内容不进入候选，不追溯补奖；
- 先按原始 question ID 分页，不合格行只推进持久化游标、不创建 Candidate，防止尾部不合格内容反复扫描；
- 只读取 ID、映射后的作者 ID、标题和创建时间，不读取正文。

内容奖励使用独立 `budget_type=content_reward`，不计入贡献毛利分母。稳定动作：

```text
action_id = content_award:{content_type}:{content_id}:{award_version}
```

删除或抄袭只能沿原 Grant/source_ref rollback；禁止换 key 重发或直接改历史金额。

VitePress 负责长文、教程和 SEO；Answer 负责问答与讨论。上线前准备模型评测、故障复盘、Provider 周报和接入教程等种子内容。博客和论坛内容本身不直接进入 Contribution/Ticket 经济账本。

## 10. 测试与上线门禁

长期保留：

- forged / expired / future / replayed Ticket；
- callback 缺失、重复、额外参数；
- flow Cookie 缺失、伪造、重放；
- Redis/Binding Guard 故障 fail closed；
- 同一 new-api ID 或 Answer ID 的并发重复绑定；
- UPDATE/DELETE/绑定时间篡改、复合索引或布尔分组削弱约束；
- 未验证 Email 不传入 Answer；
- 本地封禁不被 UserCenter 覆盖；
- Answer 本地 ID 不泄漏为 new-api ID；
- 未绑定、绑定前/同秒、隐藏、待审核内容不产生候选，连续不合格行仍推进游标；
- 全局访问日志不记录 query/Referer；callback 和敏感落地页额外关闭日志，不转发 Answer 会话/Authorization；普通 Answer API Authorization 保持可用；
- 社区网关不代理 new-api/Pulse。

真实 MySQL 回归：

```bash
FORUM_INTEGRATION_DSN='.../forum_integration?...' make test-forum-integration
```

测试会重建 Answer 测试表，因此 DSN 的 schema 名必须以 `_integration`、`-integration`、`_test` 或 `-test` 结尾；禁止指向业务库。

## 11. 工程红线

1. Answer 是社区身份事实源，new-api 是 API/资金身份事实源；
2. 论坛允许独立注册，绑定 new-api 必须可选；
3. 绑定必须一对一、不可静默换绑、不可普通解绑；
4. 浏览器 callback 参数验签前一律不可信；
5. 未绑定和绑定前内容不得产生 Pulse 内容奖励；
6. 论坛内容不得产生 contribution 或 ticket；
7. Pulse 故障不得阻断论坛本地登录或浏览；
8. Pulse 对论坛内容库只读，论坛插件的 guard DSN 不得进入 Pulse；
9. 不开启 Rank/UserStatus 代理，不让付费等级控制社区治理；
10. Answer 源码不进入本仓库。


## 12. 社区抽奖入口

METAR `/pulse` 通过同源 `/metar/api/pulse/*` 访问 Answer 认证插件，后者从原生会话、实时账号状态和保护绑定派生 new-api 身份，使用独立 community-bff 签名。普通 forum profile 密钥仍只读等级，不获得抽奖权限。社区 BFF 代码已接通；插件未配置独立密钥时权益接口不可用，`PULSE_ACTIONS_ENABLED` 与 new-api 新发奖开关默认关闭。插件扩展采用 Answer 的认证路由，禁止绕过原生认证或查询字符串 token。缺配置和 Pulse 故障只影响权益页，不阻断社区登录/浏览。

页面展示本人券与中奖结果，到账记录通过右上角弹窗入口查看，奖池概率仅在管理员预览展示。浏览器提交随机操作编号、幂等键、v3 协议版本和服务端选择凭据；同源写请求防跨站，前后端均不允许自报 user_id/amount/reward。丢失响应时查询原 action_id 或携带原选择凭据用原 key 重试，不重新抽奖。旧请求只恢复已有结果，无已提交结果时重新选择并确认。明确未扣券的业务拒绝持久保存；恢复预算后需新建操作。首版只认升级后受支持在线支付和普通同步钱包结算凭证中的 `paid_quota`。旧余额、赠送、兑换码以及未覆盖的计费路径不自动产券；不会从历史余额反推付费资格。具体支持范围、配置、发奖与撤销隔离见 [REWARDS_ROLLOUT.md](REWARDS_ROLLOUT.md)。

抽奖体验补充：中奖响应不等待经验入账；插件后台重新校验绑定后处理 EXP 领取与 ACK，额度继续由 Pulse Worker 发放。页面先揭晓已确认奖项，卡片和结果提示不显示发放/到账状态；这些状态仅在奖励记录弹窗中查看。发放中可继续浏览或在资格刷新后再次开启，并独立查询到账状态；揭晓后的历史查询延迟或失败不阻塞下一轮，已有记录、弹窗打开状态和焦点保留。短暂抽奖错误先查询原 Action，未找到才以原编号重试，最多自动恢复两次。持续故障显示“继续完成本轮抽奖”，已确认的次数不重复扣券，尚未执行的次数每次扣一张；刷新页面不会自动继续扣券。左下角“跳过蓄能”复选框保存偏好，只省略汇聚与蓄能，保留约 2.1 秒的闪光和翻牌；系统减少动态效果仍直接显示结果，不改变扣券、随机结果和发奖流程。

## 13. 社区管理员运行配置

METAR `/admin/pulse` 是独立于用户权益的管理员配置入口。只允许 Answer 当前真实管理员，实时复核 `user`、`user_role_rel`、激活与封禁；已有管理员 token 不能绕过降权。不要求 new-api 绑定，也不会将 Answer ID 当作发奖受益人。

首次在原生插件后台配置独立用途的 `admin_hmac_secret`，对应 Pulse 已有运营密钥。后续管理请求固定签名为 admin，公网别名仅代理 Answer 插件的两个固定 settings/secret 路径，不直接代理 Pulse。开关和密钥配置通过版本 CAS、幂等与审计保存；原有用户 BFF、Profile 与 SSO 权限不扩张。管理配置故障不影响本地登录/浏览。

新设置页不回显既有秘密，不在浏览器存储秘密或草稿。SSO、邮件、站点网址仍在 Answer 原生管理页配置；资金接收上限仍在 new-api。首次配对、角色私钥备份及生效规则见 [METAR 管理员配置](METAR_ADMIN_SETTINGS.md)。

### 统一后的内容入口

### 本地注册兼容

中英文插件 YAML 必须随 `i18n` Go 子包嵌入，才能由 `answer build` 的 vendoring/合并步骤保留。已有数据卷中的语言文件不会由 `answer init` 覆盖；升级时按 Answer 原生升级流程，在备份后运行 `answer upgrade -C <实际数据根目录>` 刷新语言并执行原生迁移，再重启 forum。不能把镜像构建成功等同于既有卷内语言资源已更新，数据根目录需以现有部署配置为准。

### 通知页导航一致性

富文本编辑器/多行编辑表单中的站名点击保留原生 React 路由确认；用户确认后才由既有导航桥交接。直接首页导航仅用于非编辑页面。

### 抽奖与记录展示（v0.2.48）

已绑定用户直接进入抽奖面板，不显示顶部面包屑、宣传标题和介绍段落；「开启你的脉冲」旁的问号只保留消耗用途、五连抽和奖励光色三段规则，支持点击、键盘及手机操作，按 Escape 或点击外部关闭；窄屏长文本可在浮层内滚动。固定翡翠基础光效，不再读取旧配色选择。卡片只显示图标、数量和单位，不显示档位名称、序号、完成计数或发放状态；券数仅在操作区显示一次。

未绑定元衡 API 账号的登录成员访问 `/pulse` 时同样看到抽奖舞台：券数为 0、单抽与五连抽禁用，状态提示「绑定元衡 API 账号后即可获得抽奖券并抽奖」，下方卡片提供「去绑定」入口与赠券规则说明。该页面不请求 Pulse/BFF，签到按钮只调用 Answer 经验接口领取 EXP；绑定前的签到和互动不补发券（2026-11-13）。

## 社区私聊与群组（v0.2.52）

顶部重复的“发布”入口改为“聊天”，话题列表继续保留“新建话题”。登录且已激活的 Answer 本地账号可直接使用 `/chat`，无需绑定元衡 API；原生 Answer 账号菜单也提供聊天入口。

- 按用户名查找成员，发起一对一文字私聊；同一对成员始终复用同一会话。
- 创建最多 50 人的群组（含群主和待确认邀请）；受邀者接受后入群，只能看到加入后的消息。退出、移出后立即失去读取权限，重新接受邀请也不会恢复旧历史。

- 单条消息最多 4,000 字；自己的消息可在 2 分钟内撤回。屏蔽后双方不能私聊或互发群邀请，已有共同群组不受影响。

保护限额：每人每分钟最多 120 次新写操作、每日 1,000 条消息、20 次新建/打开私聊或建群操作、100 次单独邀请和 20 次举报；新建群组的初始邀请同时受每群 50 人与每日 20 次创建限制。每人最多 100 个有效/待加入会话、200 个屏蔽对象。超过限额会明确拒绝，原请求重放不再扣限额。

本版提供文字聊天，不包含图片/文件、语音视频、在线状态或浏览器推送。消息并非端到端加密，按服务端成员权限保护；数据库及备份仍需限制运维访问。当前保留历史、幂等回执与举报审计，不自动清理；应将 Answer 数据库大小纳入容量监控，未来保留策略需另行明确后实施。

部署需同版本论坛插件、METAR 静态资源和网关路由。首次聊天请求在 Answer 数据库创建 `metar_chat_*` 表，复用 `FORUM_BINDING_GUARD_DSN`，需要建表权限；失败只使聊天不可用，不阻断普通社区登录、浏览或 Pulse。备份/恢复必须包含完整 Answer 数据库；无需新增 Redis、文件存储或独立聊天进程。GitHub Release 完成不代表已部署生产。

## 3.5 成员侧栏、草稿和社区活动

社区侧栏上方增加 `/me/drafts`「我的草稿」、`/chat`「我的消息」和 `/events`「近期活动」。手机抽屉同步这些入口；消息页复用既有私聊、群聊与未读状态，并提供 Answer 原生通知入口。通知页的社区导航同步收紧，不恢复知识库、帮助或状态入口。

草稿由当前浏览器保存，按 Answer 稳定账号 ID 隔离，最多 30 份；不上传 Pulse、不宣称跨设备同步。原生问题/回答编辑器通过共享存储适配器读写，继续编辑保留原目标，发布或原生丢弃操作只清理当前草稿。带预填信息的新建页面使用新草稿；其他标签页已更新的草稿拒绝旧版本覆盖。旧版未归属草稿需用户确认归属后导入，未登录不展示内容。清理站点数据会删除本机草稿，重要内容应另行备份。

社区活动是公告与免费报名，不是 Pulse 奖池。管理员从 `/admin/events` 发布标题、说明、地点、开始/结束时间、报名截止与人数上限；开始前可编辑，取消后关闭报名。普通激活成员报名或取消本人报名，未登录者可浏览；公开页面只展示人数，名单仅当前管理员可读。活动结束后进入往期列表。数据库事务保证最后一个名额不会被重复占用，同一请求重试不会再次报名或发布；未确认的浏览器操作保留原请求供重试。活动数据不会产生贡献值、券或自动奖励。

## Pulse 社区中奖动态

抽奖页普通用户统一看到“匿名用户”；Answer 管理员可以看到中奖人的社区用户名。默认预览五条，“查看更多”显示全局最近 100 条已到账奖励，不再限制近 30 天；同一用户多次中奖仍为多条记录，历史奖励和账本不删除。

普通用户仍经会话、状态和绑定校验；管理员通过独立 admin 签名与实时角色复核读取名称。接口不提供分页或用户筛选。管理员接口失败清空含名记录，普通匿名动态临时失败保留上次结果，权限失效均清空。详见 [架构说明](ARCHITECTURE.md#匿名社区中奖动态)。


## 帖子与回答自动导入外链图片

原生发帖、回答和编辑页面的编辑器自动识别 Markdown 图片；富文本粘贴由 Answer 转成 Markdown 后同样处理，无需用户逐张保存。导入按顺序执行：服务端下载 → 原生图片上传 → 成功后替换正文中的图片地址。编辑器显示进度，导入期间等待完成后再提交；失败保留原地址并提供「重试图片」，可继续编辑正文。打开已有内容或恢复草稿也会识别外链，浏览帖子不会下载、上传或改写历史正文。

相同来源在当前编辑器会话中只上传一次；普通超链接、行内/块代码、本地图片不处理。引用式图片转为内联图片，原引用定义和普通链接保持原样。删除图片、切换账号或离开编辑器后不使用迟到的结果覆盖正文。外部 Storage 返回的地址在本次编辑中不会重复导入；默认本地上传地址在以后编辑时也会跳过。

下载仅接受公开 HTTPS 图片（标准 443 端口），支持 PNG/JPEG/GIF/WebP，单张最多 5 MiB、2000 万像素、总下载超时 15 秒；一次自动扫描最多排入 30 个来源。服务端每进程最多 4 个下载、每账号同时 1 个及每分钟 60 次，超限或来源拒绝访问均保留原图。原生上传仍执行本站更严格的大小、格式和权限规则，未知上传结果允许重试但不保证零重复文件。

图片继续由 Answer 现有上传接口、文件记录与 Storage 管理，默认文件属于 Answer `/data` 备份；未发布的上传沿用原生孤儿文件清理。不增加 Pulse/new-api 依赖，不配置新的公共图片代理，不自动转载或发布文章。来源无法下载时仍可手动上传。

赠券复用现有奖池、单抽/五连抽、额度资格期限和预算。功能需部署同版 Forum、Pulse API/Worker 与前端，发布 GitHub Release 不等于生产上线。

## 注册邮件发送结果反馈

Answer 1.7.1 通过构建补丁同步执行注册激活邮件、用户重发、管理员重发及后台 SMTP 测试。只有邮件服务完成 SMTP DATA 接收才返回成功；缺 SMTP 配置、激活码缓存失败、连接/认证/投递失败返回 HTTP 503 与本地化提示「发送失败，请稍后重试」。浏览器对这两类邮件错误展示原生弹窗，不切换整个页面为服务故障页。

注册已创建账号后发信失败时，账号保留待验证状态，提示登录后重发，无需重复注册；不删除账号、不绕过邮箱验证。失败后清理验证码弹窗，下次重发重新验证。SMTP 交换有 8 秒总截止时间，TLS 模式要求 STARTTLS，保留 465 隐式 TLS 及 PLAIN/LOGIN/CRAM-MD5 认证。发送成功只代表 SMTP 接受，不保证最终进收件箱；超时也可能存在结果不确定。

修改需要重新构建并部署 forum，并按原生升级流程刷新已有数据卷的语言资源。测试入口为 `make test-forum-mail-errors`，生产邮件配置和真实收件仍须单独验收。

`/me` 侧栏不再显示“我的集市发布”，“签到抽奖”使用站内 `/pulse`，即使未配置元衡控制台地址也可访问。社区壳层与 Answer 原生页共用 `back-button.css`，以个人中心的箭头描边返回按钮为基准；聊天返回列表与错误页返回入口同步采用该样式，返回目的地不变。顶部布局以 marketplace 为基准，latest 隐藏返回控件但保留空白占位，主页也保留顶部搜索框；选中导航项不改变文字宽度。需要配套更新社区静态资源和 forum 插件。

### 论坛前端资源完整性

Answer 构建先运行 Go vendor，再从其中的 package.json 发现 UI 插件。user-center-pulse 和 captcha-turnstile 必须显式嵌入前端入口、相对导入及样式。`make test-forum-frontend-assets` 检查递归依赖并用真实 Go vendor 验证文件保留；Docker 构建在 answer build 前执行依赖检查。

部署后运行 `python3 services/forum/verify_frontend.py --base-url https://metarhub.com` 检查登录页，并加 `--path /questions/<有效帖子ID>` 检查详情页；脚本检查 HTTP 状态、主脚本与样式引用、资源非空且不是 HTML 回退。主脚本缺失时，Answer 服务端正文虽已返回，加载遮罩仍无法移除。此检查不替代登录、验证码与发帖交互验收。

论坛构建在编译最终二进制后用隔离安装服务验证内嵌入口与首屏 JS/CSS，不需要业务数据库。React 构建曾因格式错误返回零却未产出入口，不能仅凭构建命令退出码判定可用；上线后仍须运行原生登录及帖子页面检查。

### 帖子列表采纳标签

首页、个人帖子及收藏共用列表将 Answer 的 `accepted_answer_id` 字符串 `"0"`、数值 0、空值及非法值视为未采纳，不显示状态标签。有效正整数回答 ID 才显示“已采纳”（英文 Accepted）；十进制字符串保持原样判断，避免大整数精度丢失。采纳及取消操作仍由 Answer 原生接口负责，列表重新获取状态后反映结果，不新增独立“已解决”开关。

### Pulse 签到自动同步

Pulse 页签到后每 5 秒读取任务进度，最多自动重试 12 次；确认独立 checkin_delivered 标志为真、待交付任务完成且权益刷新实际成功后结束检查。部分到账也更新可用券，此前评论等获得的券不作为签到到账依据，刷新遇忙跳过则继续重试。异步赠券服务仍是事实源，不在浏览器直接增加券数。离页或身份变化停止后续读取和更新；响应丢失时只读查询恢复，入账延迟则保留已签到状态并提示在页面内继续刷新。

### 帖子列表发布者

Answer question/page 增加独立 `user_info`，以帖子持久化 UserID 获取公开用户资料，复用原有批量查询。`operator` 保持最近活动者语义；兼容旧接口时，仅 operation_type 为 asked 且缺少 user_info 才将其作为发布者，回答和编辑活动不得兜底为作者。共用 questionRow 使用 user_info 渲染头像、昵称和个人主页链接，等级组件依同一主页识别发布者。资料缺失时不伪造作者。需配套更新 forum 镜像和社区静态文件。

### 后台返回与头像入口

顶部返回使用当前标签页记录的同源进入页面；所有 `/admin` 子页面视为同一区域，后台同级切换不覆盖进入后台之前的来源。未记录来源时后台返回 `/me`。左侧“返回网站”和站名链接仍返回社区首页。个人中心头像始终保留真实 `/me` 链接，避免返回其他页面后因复用顶部栏而失去点击入口。

用户管理宽表格最右侧操作列固定可见，三点按钮附加“操作”文字，不改变账号切换、赠券或其他管理操作的权限与确认要求。

### 批量运营发帖和回答

管理员可从个人中心进入“内容运营”，选择登记的专用运营账号，预览并确认一批话题或指定帖子下的回答。JSON 文件或粘贴导入支持定时发帖、回答和楼中楼，parent 关联同批内容，关页后服务端继续执行，支持取消剩余项。每批最多 20 项，公开正文标注运营代发，管理员会话保持不变。登记、逐项请求和结果均可审计，未知结果不自动重复发布。使用限制、导入样例、存储和部署见 [内容运营说明](CONTENT_OPERATIONS.md)。

### 评论与回答的界面区分

帖子详情沿用 Answer 的两级内容：原帖评论显示“帖子评论”，回答下的评论显示“回答评论”。入口及提交按钮区分“评论帖子”“评论此回答”和“发表回答”，评论间回复标明“回复这条评论”。正式回答计数和采纳功能保留，不迁移或合并已有内容。实现为 `answer-discussion-labels.patch`，需重建 forum 并按既有升级流程刷新数据卷中的语言资源；仅更新社区静态壳层不会改变原生详情页。

### 紧凑帖子列表（2026-11-13）

首页与分类列表复用现有 Answer 筛选/分页。每行显示发布者头像、标题、最多 28 个 Unicode 字符的正文摘要、发布者和发布时间；右上显示正式回答数，右下最后回复信息与左侧元信息对齐。该计数继续使用 Answer 的 answer_count，不混入帖子评论或回答评论。手机空间不足时最后回复另起一行。个人帖子和收藏复用相同布局。

最后回复来自列表新增的 last_reply（公开回答作者与发布时间），不使用最后编辑者替代。零回答显示「暂无回答 · 等你分享经验」；有回答但旧接口或非公开最后回答未提供信息时显示「已有回答」。完整展示需同时部署 forum 作者补丁与社区静态资源；不会改变排序、内容权限和奖励规则。

右栏「等你来回答」读取未回答列表前 5 条；「精选阅读」读取既有 `feeds`（好文收藏）标签按高赞排序前 5 条。两块使用真实公开内容，独立异步加载，失败或空内容有明确提示，隐藏两个模块的查看全部入口，帖子之间以细分隔线和留白区分，已关注标签保留其后。精选阅读并非新建人工审核机制，内容继续由现有标签管理。

首页精简更新：顶部搜索为唯一搜索入口，准则移到辅助区；每帖显示一个主分类及短摘要，列表不显示等级。排序常驻最近活跃/最新发布/待回答，热门与高赞在更多中。待回答显示三条，精选可展开；未关注标签时不显示空卡片，仍可由标签目录关注。手机辅助内容默认折叠。列表页页脚随内容滚动，其余页面保持原规则。

### 个人中心同级切换

从「我的」进入个人空间、成长、收藏、绑定、勋章、账号设置、通知和草稿时保留个人菜单；聊天和 Pulse 也可在相同外框切换。账号设置的资料/通知/账号/界面继续由 Answer 保存，嵌入白名单同源页面，未保存离开会提示。勋章详情返回列表，同级功能返回跳出个人区域；管理员后台和元衡网站为独立入口。新入口 /me/settings、/me/badges，旧原生 URL 仍可独立使用。部署需更新社区静态资源与 Nginx；未部署同源页面白名单时可通过“在独立页面打开”继续使用。
