# Vibe Coding 集市产品方案

日期：2026-11-07。状态：产品提案，尚未实现或上线。交互原型中的作品、作者和互动均为示例。

## 产品定位

让成员发布 AI 辅助开发的作品、体验应用，并把待解决的问题变成后续作品。核心过程：发现项目 → 体验 → 讨论反馈 → 作者迭代；想法讨论 → 有人开发 → 关联项目。首期以分享与共创为主，不建设交易或创作者分成。

## 现有能力与复用

已核对 `metar-frontend/production/src/taxonomy.js` 与 `metar-frontend/shared/routes.json`：类别来自 Answer 推荐标签，类别页为 `/topic/:slug`；当前没有项目集市或运行页面。Answer 已有身份、账号状态、帖子、回答/评论、收藏、草稿和内容治理。集市复用这些能力，新增项目结构化字段与展示，不另建社区账号和评论系统。

“只加类别和发帖模板”可以低成本试运营，但演示、费用、开源与用途难以集中发现。推荐增加专属展示页，正文与互动仍归 Answer。完全独立的应用市场会重复身份与治理；首期直接托管代码则需要独立构建、运行资源和成本管理，暂列后续。

## 入口与页面

左侧“类别”中增加「Vibe Coding 集市」，建议紧邻“开发实践”。桌面、手机抽屉、类别目录及原生 Answer 页面入口同步。同名 Answer 推荐标签承载内容归属，专属页面负责集市浏览，不另造一套分类事实。

建议路径 `/marketplace`；同名类别 `/topic/vibe-coding` 交接到同一集市，保留筛选，避免两份列表漂移。路径和 slug 均为建议，实施前核对冲突并进入共享路由生成流程。

默认进入“项目”，第二页签“想法讨论”；“我的发布”是个人管理入口。沿用现有绿色、紧凑社区壳层，从搜索、筛选和发布操作开始，不增加大幅宣传区域。

| 页面 | 主要内容与动作 |
|---|---|
| 项目首页 | 搜索；用途、可在线体验、源码/开源筛选；最新更新/精选；项目双列卡片，手机单列 |
| 想法讨论 | 问题、目标人群、期望效果、进度、需要的帮助；评论/收藏/支持 |
| 项目详情 | 用途、截图、操作示例、限制、费用/数据去向、作者、仓库、许可证、更新时间 |
| 在线体验 | 主动点击后加载；保留说明、外站打开、返回详情和举报 |
| 发布入口 | 先选择“发布项目”或“讨论想法”，再显示对应字段 |
| 我的发布 | 草稿、待审核、已发布、需修改、已下架；编辑与演示可用状态 |

### 项目卡片

名称、一句话用途、封面/应用截图、作者、用途标签、在线能力与费用。先让用户理解“能帮我做什么”，AI 开发工具放次要位置。

主操作按能力为“站内体验”“访问演示”或“查看项目”；源码入口独立为“GitHub”。点击项目名称进入详情。状态区分“站内体验 / 外站演示 / 仅源码 / 体验暂不可用”。有公开仓库只标“源码可见”，许可证符合开源定义才标“开源”。

首期排序使用最新更新和人工精选，数据足够后再开放近期热度；不按单纯访问量排名，重复点击和作者自刷不能增加有效热度。用途可从效率工具、内容创作、开发工具、学习教育、趣味实验起步，不强制过细分类。

### 项目详情与互动

顶部集中显示用途、作者、在线/源码入口、费用与使用要求。正文提供截图、适用人群、操作示例、已知限制、使用的开发工具和更新记录。“介绍 / 在线体验 / 讨论”共享一个项目，不复制评论。没有演示时不出现可运行假按钮。

沿用 Answer 收藏、评论/回答、账号资料、通知与举报能力；如何将原生互动完整嵌入专属详情，应在实施前验证插件扩展点。无法完整复用时，讨论入口打开关联原生帖，不制作第二份评论。

## 发布与维护

“上传项目”首期指提交链接、截图和说明，不意味着上传源码包或自动部署。支持 GitHub-only、演示-only、二者都有，至少提供一个有效入口。

| 项目字段 | 要求 |
|---|---|
| 名称、一句话用途、详细介绍、用途标签 | 必填 |
| 作者关系 | 本人/团队作品，或推荐收录；推荐收录保留原作者署名，不获得维护身份 |
| GitHub / 在线演示 | 至少一个；首期收录公开仓库，不收私有仓库凭证 |
| 访问方式 | 有演示必填：站内体验申请或外站演示、是否需登录 |
| 费用与 AI 依赖 | 有演示必填：免费/有限免费/收费、是否使用 AI、由谁承担费用 |
| 输入数据去向 | 有演示必填：输入发给谁、是否保存或使用外部服务 |
| 封面、截图、开发工具、技术栈、操作示例、限制 | 可选，鼓励补齐 |

首期允许手动填写仓库信息；GitHub 解析失败不阻断人工填写。费用有第三方依赖时不得笼统标“免费”。项目审核状态与演示可用状态分别展示。

发布流程：草稿 → 提交审核 → 已发布；需要补充则返回“需修改”，违规可下架。首发人工审核；运行地址、域名或作者归属变化重新审核，通过前沿用旧的已审核版本。普通说明更新沿用原生内容治理。作者可以编辑、关闭体验和下架；重复提交或丢失响应不能创建重复项目及讨论。

## 想法讨论与作品关联

想法表单必填“为谁解决什么问题”和“希望怎样使用”，可选当前替代做法、输入/输出例子、希望得到的帮助。进度为“征集反馈 / 开发中 / 已有作品 / 暂停”。

支持评论、收藏和表达“我也需要”。首版可沿用原生点赞表达支持，保留其原生语义；若新增独立需求计数，不与点赞相加或冒充点赞，并单独核对任务采集。交互原型只演示意愿表达，不代表现有独立接口。

“发布关联项目”预填想法内容，发布成功后原帖仍保留，顶部展示已诞生的作品；项目页回链来源。一个想法可关联多个项目，多人可各自实现，归属不能自动转给想法发起者。合作沟通先复用现有评论和聊天，不建设接单、竞价和付费悬赏。

## “站内调用”的分级设计

| 方式 | 用户体验 | 建议 |
|---|---|---|
| GitHub 收录 | 查看说明，前往仓库，按作者说明使用/部署 | 首版支持 |
| 作者部署的在线应用 | 外站打开；允许嵌入并审核后可在本站体验 | 首版支持 |
| 平台托管运行 | 上传源码、构建、部署、隔离执行与资源管理 | 后续单独立项 |

首版“站内体验”指嵌入作者已部署的应用，不表示 METAR 运行任意仓库。只接入审核通过的 HTTPS 演示，在独立来源与最小嵌入权限下运行；论坛会话和 API 密钥不传给项目。拒绝嵌入的站点或需要不适宜嵌入权限的应用，提供外站演示，不通过反向代理绕过作者策略。失败时清楚提示，并保留外站入口。

浏览、发布、收藏和讨论使用 Answer 账号，不要求绑定元衡 API。首期不自动动用访问者的元衡余额。作者承担试用成本时需有独立限额；需要用户自己的 Key 时在作者应用中配置，METAR 不做统一收集 Key 的表单。未来如提供“用我的元衡额度”，需另行设计明确授权、模型与金额限额，以及 new-api 原生调用/计费接入；不能由 Pulse 代理模型请求。

项目提交、浏览、运行、收藏和需求支持不产生新贡献或赠券渠道；原生讨论如符合既有社区任务规则，仅按既有规则统计一次。

## 数据与工程建议

建议在 Answer 插件扩展中保存结构化项目元数据，引用稳定的 Answer 作者和讨论 ID，随 Answer 数据库备份。正文、评论与身份仍归 Answer。类型、可见性与运行地址必须由服务端校验，不能依赖任意标签或浏览器自报用户 ID。

实施前验证原生创建/编辑扩展点和正文/元数据的一致性。不能同事务保存时，使用可恢复发布流程：草稿不公开、关联完成才公开、原请求可查询恢复，避免孤儿讨论与重复项目。本提案不预定未经验证的具体表名或 API。

## 分期与运营

1. 首版交付类别入口、项目展示和链接收录、想法讨论与作品关联、最新/精选、搜索/筛选、收藏、作者维护和人工审核；少量合格演示支持站内嵌入，其他外站体验。
2. 根据反馈补仓库信息同步、链接可用性检查、更新订阅；用户反复需要快速部署时再评估一键部署。
3. 平台托管、统一 AI 调用、收费与创作者分成分别立项，先明确资源、成本与运营归属。

冷启动建议人工准备 10–20 个可用作品、5–10 个真实问题想法，覆盖不同用途，再开放投稿。数量为运营建议，并非现有数据。每周安排一轮作品试用反馈和作者回应。

主要观察“每周获得有效体验反馈的项目数”：作者之外的成员描述实际使用情况。辅助看详情到体验入口点击率、作者七日回应率、想法关联作品数、持续更新的作者比例。按钮点击或 iframe 加载不能算成功调用；成功体验需要应用提供经验证的回执，或用户主动反馈。比率展示观察窗口和分母，首两周建立基线后再定目标。

## 实施验收范围

- 桌面、手机和原生侧栏入口一致，集市与类别深链接指向同一内容；刷新、前进后退及分享链接可用。
- 游客浏览、登录发布、未绑定账号互动、被封禁/未激活账号拒绝写入均符合 Answer 权限；运行与费用无隐式授权。
- GitHub-only、演示-only、二者都有、失效/拒绝嵌入均有准确操作；拒审、编辑重新审核、下架后直链和搜索可见性一致。
- 草稿、提交失败、响应丢失、重复提交和跨入口编辑可恢复，不能重复创建内容或绕过运行配置审核。
- 想法关联多个作品，保留原讨论和正确作者；原生互动不能重复记任务赠券。
- 320/390px、桌面、中英文、深浅主题、键盘操作与加载/失败状态完整；原型示例不进入生产。
- 真实演示浏览器验收来源隔离、权限和嵌入失败，不泄露会话/密钥；运行不可用不阻断社区浏览与讨论。

本轮仅产品设计与交互原型。正式实施时同步架构、社区说明、能力地图、决策笔记和共享路由，并完成相应业务验收；不把原型校验当作业务上线。
