# Vibe Coding 集市

日期：2026-11-07。本文描述首版实现；生产更新与验收独立于本地构建。原产品交互示例不作为线上项目或真实统计。

集市让成员分享 AI 辅助开发作品、在线体验和讨论想法。项目可来自公开 GitHub、作者部署的 HTTPS 应用或两者；站内体验为审核后嵌入作者应用。源码构建托管、平台统一模型调用、交易与分成另行立项。

## 入口与发现

- 左侧「类别」固定入口，顶部和原生 Answer 页头同步；普通类别仍由 Answer 推荐标签管理。集市无需写入推荐设置，`/topic/vibe-coding` 兼容跳转到 `/marketplace`。
- `/marketplace` 默认项目，第二页签为想法讨论；支持关键词、用途、在线演示/GitHub、最新/人工精选及分页。
- `/marketplace/item/:id` 显示作者/推荐来源、摘要、技术栈、许可证声明、费用、访问和数据说明，提供体验、GitHub 与原生介绍/讨论/收藏入口。
- `/marketplace/mine` 显示本人草稿、待审核、已发布、需修改、已下架和审核说明。管理员头像菜单提供 `/admin/marketplace`。

详情的正文、图片、使用示例、回答、评论、点赞、收藏和举报复用关联 Answer 原帖，不复制一份互动系统。公开仓库不等于开源，不在缺乏许可证证据时标记“开源”。

## 发布与维护

`/marketplace/publish` 使用两步发布：先用预填原生编辑器创建介绍/讨论帖，再返回选择本人帖子或粘贴 URL/数字 ID，填写集市元数据。原帖按 Answer 原有权限发布；集市的草稿或待审核信息不进入公共列表。原生编辑器继续负责验证码、正文、上传与草稿，避免两个系统并行创建正文及重复讨论。原生发帖未完成时，保留原生草稿并回到原编辑器恢复。

| 字段 | 首版要求 |
|---|---|
| 介绍帖、项目/想法类型、用途、作者关系 | 必填；原帖必须属于当前正常已激活 Answer 账号 |
| 一句话说明 | 提交审核时 5–280 字 |
| GitHub / HTTPS Demo | 项目至少一个；拒绝凭证、查询参数、片段、IP、localhost/内部域名与 METAR 自身域名；只接受标准公开仓库 URL |
| 原作者 | 推荐收录必填，署名与本人/团队作品区分 |
| 费用、访问与 AI 付款要求、输入数据去向 | 有演示必填；由投稿者声明并人工核对 |
| 嵌入许可申请 | 作者获得许可后勾选，仍需管理员批准 |
| 技术栈、许可证、来源想法 ID | 可选 |
| 想法进度 | 征集反馈、开发中、已有作品或暂停 |

每个原帖最多一条收录，项目/想法类型和原帖 ID 创建后不可变。一个想法可被多个独立项目关联，作品和想法详情双向回链；不会自动转移作者身份。想法详细问题、人群、使用方式和需要的帮助填写在原生介绍帖中。

状态为草稿 → 提交审核 → 已发布；管理员可退回需修改或下架。待审核版本不可直接编辑；作者可撤回再编辑。已发布作品可提交更新审核，旧审核通过的元数据继续服务，直到新版本批准；费用、运行地址、归属更新不能绕过审核。作者下架即时停止公共展示，原介绍帖保留。管理员可独立更新演示可用性、嵌入许可和精选。

相同请求重试保留同一 Idempotency-Key，恢复首次结果；相同 key 更换 payload 冲突。浏览器按账号暂存未确认命令，重载后可“重试原操作”，避免响应丢失造成重复收录。写入需可靠站点存储，浏览不依赖存储；版本变化要求重新核对，不能静默覆盖。

## 体验与经济边界

GitHub-only 项目打开仓库，Demo-only 项目打开演示；只有申请并审核通过且演示状态可用的项目出现「站内体验」。点击时再次读取 live 元数据，再创建 iframe，不以访问详情自动加载第三方应用。

iframe 仅授予脚本与表单，禁止 same-origin、顶层导航、弹窗、下载及摄像头/麦克风/定位/支付/剪贴板写入；no-referrer。METAR 不传递论坛 Token、Cookie、API Key、余额或付款授权；第三方自身 Cookie 遵循浏览器策略。拒绝嵌入或受限功能通过外站演示使用，不反向代理绕过作者策略。frame 加载事件不代表应用或模型调用成功，因此始终保留中性提示与外站回退。

浏览、投稿、运行和关联不新增 Contribution/Ticket/Reward 来源。原生介绍帖的有效互动仅按已授权社区任务规则统计一次。项目 AI 成本由作者说明，站内不自动动用访问者的元衡余额，也不统一收集用户 API Key。

## 服务端与运维

Answer 是用户、正文、互动、治理事实源。插件在同一 Answer MySQL 中维护 `metar_market_item`（投稿/live 快照）、`actor`（限流/串行化）、`request`（规范化指纹与回执）、`audit`（版本与前后值审计）。元数据、审计、限流计数和回执同事务；独立连接池，不访问 Pulse/new-api 数据。首次使用加 schema 锁创建表，随现有论坛数据库备份。

公开读取每次联查帖子 status/show、归属和作者激活状态；隐藏、删除、封禁和下架后停止展示。用户写入经 Answer 会话和实时 MySQL 状态，管理员额外查当前角色；浏览器自报 user_id、跨源写、重复/未知 JSON 字段都被拒绝。

| 接口前缀 | 用途 |
|---|---|
| `/answer/api/v1/metar/marketplace/items`、`items/:id` | 游客公共列表/详情 |
| `/answer/api/v1/metar/marketplace/mine`、`command` | 已激活本人列表、草稿/提交/下架命令 |
| `/answer/admin/api/metar/marketplace/admin/items`、`admin/command` | 当前管理员审核队列与命令 |

## 验证与后续

本地验证使用 `make test-community`、`make deploy-test`、`make deploy-config-test`、共享路由检查及决策笔记校验；论坛插件测试和 `go vet` 使用显式模块路径。MySQL 100 路并发、原响应恢复、空回执恢复、审核快照、权限、想法关联、搜索转义和封禁/下架验证使用 `make test-marketplace-integration`，必须是专用 `_market_test` 库。

生产必须通过 `deploy/update.sh --ref main` 备份、构建、迁移和健康检查，再核验公共与私人深链接、匿名 API、登录交接、实际普通账号发布/审核及真实第三方 iframe 的限制。不把夹具或编译通过当作已完成生产账号验收。

可继续完善的运营能力：封面卡片、仓库信息同步、链接定期探测、作者更新订阅及更完整的发现指标。首版精选与可用性人工维护；不虚构冷启动项目、作者、访问量或应用成功调用数。
