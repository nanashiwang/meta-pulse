# 管理员内容运营

入口：个人中心 → 管理 → 内容运营（`/admin/publishing`）。仅正常且已激活的社区管理员可访问；元衡 API 管理员身份不替代社区权限。

## 操作流程

1. 在用户管理创建专用运营账号，或使用现有专用账号。目标必须已激活、正常、普通用户，且未绑定外部登录/API 账号；管理员切换产生的本地别名不算外部绑定。
2. 在内容运营页填写用户名与登记原因，登记为运营账号。登记本身不修改密码、角色或绑定。
3. 逐条选择账号，填写话题标题、正文、标签，或填写已有帖子编号和回答正文。每批最多 20 项。
4. 点击“加入待发布列表”，核对预览。可通过“批量导入准备好的内容”粘贴 JSON 数组，导入不会自动发布。
5. 勾选确认账号、内容和转载许可，点击“确认发布本批次”。页面逐条提交并显示结果，原生审核规则可能使内容暂未公开。
6. 出现网络或权限问题时批次暂停。继续按钮使用原来的请求编号核对；不要把未知结果复制成新批次重发。离开页面/切换登录账号会停止后续提交，已经提交的记录仍保留。
7. 发布话题成功后可从结果链接取得帖子编号，再在下一批添加该话题的回答。

正文由服务端追加显式“运营代发 / Posted by community operations”和唯一审计编号，有来源时附 HTTPS 来源链接。用户原文按 Markdown 交给 Answer 渲染；预览显示文本而不执行 HTML。需要转载许可，不提供自动抓取外站或伪造自然用户互动。

示例（将用户名与帖子编号替换为真实值）：

```json
[
  {"username":"community_editor","kind":"question","title":"分享一个实用的开发经验","content":"这里填写不少于六个字的真实内容。","tags":["news"],"reason":"社区内容建设","source":"https://example.com/article"},
  {"username":"community_helper","kind":"answer","question_id":"10010000000000243","content":"这里填写与该话题相关的回答。","reason":"补充讨论资料"}
]
```

## 权限与存储

- 接口位于 `/answer/admin/api/metar/publishing`：GET 查看账号和最近 100 项审计，POST `/accounts` 登记专用账号，POST `/item` 提交/核对单项。
- 每次重查实时管理员身份和目标资格，同源写请求、JSON 严格解码、每位管理员每分钟最多 20 个新条目；单条请求最大 64 KiB，正文最大 50,000 字节。
- Answer DB 新增 `metar_operator_account` 与 `metar_operator_publication`。首次接口调用建表；账号登记保存管理员和原因，发布项保存管理员、目标、请求键、内容、摘要、标识和结果。纳入论坛数据库备份。
- 相同管理员 + 请求键 + 内容重放返回原结果，内容变化返回冲突。MySQL 命名锁避免同项并发调用原生发布。先保存 running 再调用；意外中断后按唯一正文标识查询已写入内容，没有找到则保持待核对，绝不自动重发。
- 原生适配器不对外提供身份指定接口；目标只由服务端资格查询决定。独立 Gin 上下文移除管理员凭据，只赋予普通目标账号角色，不改变管理员会话；唯一例外是管理员确认的专用调用免交互验证码。原生目标声望、标签、重复回答限制、内容校验和审核继续执行。
- 不授予 Pulse 权限，不直接写财务账本。代发内容进入正常社区内容和经验统计；目标须无外部绑定。若要将运营内容从运营分析或互动赠券来源中排除，需要独立规则变更，当前不冒充已排除。

## 部署与验证

需配套更新 forum 镜像、社区静态前端和网关路由。普通源码推送不等于部署；已有网站不会自动出现新入口。

`make test-operator-publishing` 验证全部补丁可叠加、原生身份隔离、发布权限、请求重放和未知结果恢复。前端 `admin-publishing.test.js` 覆盖导入上限、预览转义、逐条执行、中断和身份切换；正式构建包含页面脚本。生产首次验收应使用专用运营账号和经确认的内容。
