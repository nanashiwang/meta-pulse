# 社区账号管理

用户管理入口为 `/admin/users`。每行三点菜单的 **赠送抽奖券** 可给已绑定 API 账号的用户手动发券：输入数量（1–100）和原因并确认，券立即到账，额度资格按当前规则有效天数计算；网络不确定时按提示重试同一请求，不会重复发放。未绑定账号会提示无法发放。原生「添加用户」支持批量创建，按“姓名, 邮箱, 密码”填写，每行一个；邮箱可以留空，例如 `社区用户, , Passw0rd`。留空邮箱时账号仍按 Answer 原生管理员创建流程保持可用，但 Answer 的密码登录使用邮箱作为登录名，因此该账号不能通过邮箱密码登录或邮件找回，也不能自动绑定 new-api；需要邮箱登录的用户应提供邮箱。提供邮箱时仍校验格式和重复；账号、密码校验及角色继续由 Answer 管理。

首次使用切换功能，在后台「插件」启用 **管理员账号切换**（`metar_admin_switch`），主 `pulse_user_center` 插件也需启用。随后在用户列表目标用户所在行点击右侧三点菜单中的「切换登录」并确认；切换入口收在原生行操作菜单内，不额外增加表格行高。已激活的普通用户及版主可作为目标，自己、其他管理员、未激活/封禁/删除账号会被拒绝。

切换后以目标账号的真实权限操作，页面底部提供「返回管理员」。返回会复核原管理员会话并注销本次切换会话；原会话过期时使用正常登录页重新登录管理员。

原生会话在同源标签页间共享，切换时其他已加载新版脚本的标签页自动刷新。返回凭据仅保留在发起切换的标签页 `sessionStorage`；关闭标签页后可正常重新登录。该功能不修改密码、角色、new-api 绑定或余额，不自动创建 API 账号。禁用插件关闭新的切换；已登录会话仍由 Answer 的注销、密码重置和封禁规则管理。

交接票据有效 60 秒、仅能消费一次，绑定发起管理员的原会话；签发和消费均实时检查账号状态。Answer 库 `metar_admin_switch` 记录操作者、目标、时间、交接及返回授权，只有票据和会话的 SHA-256，不保存原始凭据；随论坛数据库备份。`user_external_login` 中独立 `metar_admin_switch` provider 仅存本地账号别名，不属于 API 绑定，也不能通过公共登录入口自行发起。

发布后需要一起更新 Forum 镜像和 METAR 静态资源；升级与插件启用是独立操作。验证命令：`make test-account-switch-integration`、`make test-community`、`make build-forum`、`make build-community`。集成测试必须使用专用、可重建的测试数据库。

## 用户列表统计

`/admin/users` 不显示最左侧序号，保留 ID 与头像昵称列。统计列默认显示，可通过列设置隐藏；点击列头或选择排序字段，可在全部筛选用户范围内升降序排列：

- 抽奖券剩余量：Pulse 历史券账本当前净余额，含各规则版本；额度资格到期不等于券失效，仍可抽经验。
- 校正累计获券：迁移 00021 为已有用户保存统计基线，校正时等于当时已消耗券，此后新增正向发券正常累加；副行的清零/撤销/过期从校正后重新累计。可用券、历史已消耗券与到账奖励不变。原始流水仍保留用于审计。此口径按用户要求不把校正时剩余券加入累计，不能再用“累计减消耗减清零”反推可用余额。
- 已消耗券：`ticket_spend` 的净消费量，清零、撤销和过期不算抽奖消费。
- 已到账奖励：仅 `pulse` 抽奖、`settled` 且未撤销的奖励；额度按当前 `quota_per_unit` 显示 ⚡，经验显示 EXP，二者可分别排序，不混合相加。倍率未知时显示原始 quota 单位。
- 发帖数：有效主帖（含已关闭），不含已删除或待审核帖子；实时统计暂不可用时使用原生用户列表返回的发帖计数。
- 发帖获赞数：上述主帖收到的未取消正赞，不是正负投票净分。
- 评论数：有效回答与楼内评论合计。
- 点赞数：用户主动给主帖或回答的未取消正赞。
- 帖子被分享数：本版本上线后有效主帖的分享按钮点击次数，可重复，支持匿名点击；不表示已完成外部转发，不回填历史点击。桌面打开分享菜单计一次，菜单内选择渠道不重复计数；移动端直接分享计一次。

社区统计读 Answer；券统计只通过 Pulse 管理员签名接口读取。未绑定或接口不可用显示「—」，不把缺失数据当零。分享不要求绑定，不产生券、经验或奖励，接口要求同源并限流。默认分页只查询当前页最多 100 人。选择排序时，浏览器复用原生筛选按每批 100 人加载全部结果及统计，再排序和分页；大整数精确比较，同值按用户 ID 升序，未绑定缺失值始终排最后。全量加载期间不展示部分排名；任何批次失败、数量变化、重复 ID 或超过 60 秒会提示重试或缩小筛选范围，切换筛选与离开页面会取消请求。排序和方向保存在 URL，可用“默认排序”回到原生分页。统计是分批实时查询，不承诺跨服务同一时刻的事务快照。
