# METAR 界面统一实施记录

目标：绿色 METAR 为统一视觉；用户常用页面最终在同一套布局内完成操作，Answer 继续作为社区身份、内容与权限事实源。每个阶段独立验证、中文提交并 push，按现有流程发布；代码交付和生产部署分别记录。

| 阶段 | 范围 | 状态 |
|---|---|---|
| 1 | 共享路由清单、原生导航接入、登录回跳和历史恢复 | v0.2.1 代码与本地验证完成；生产待升级 |
| 2 | 共享视觉、Answer 页面和博客外观、主题与统一导航 | v0.2.3 代码与独立本地 Answer 验证完成；生产待升级 |
| 3 | 公开资料、内容互动、通知和发布流程 | v0.2.4 代码与本地原生收藏/导航验证完成；生产待升级 |
| 4 | 登录注册、账号设置、管理入口和旧链接收尾 | v0.2.5 代码与本地验收完成；生产待升级 |

验收必须覆盖：点击/直达/刷新/后退一致；公开资料与私人空间权限分离；旧回答/评论/邮件链接可定位；未激活/封禁/过期会话保持后端权威；移动端、暗色和语言持久化；编辑器草稿/验证码/上传/审核流程无缺失。替代页面未验收前不重定向旧写入口，不将外观统一冒充功能迁移。

## 内容入口收拢

原生页面已接入共享视觉后，完整互动能力继续复用 Answer，不重写富文本、上传、验证码、评论、审核和权限逻辑。列表、搜索与收藏直接链接 `/questions/:id`，搜索回答保留回答 ID；作者链接原生公开资料，`/me` 仍是当前会话的私人入口。删除重复只读详情和通知视图，`/question/:id` 与 `/me/notifications` 兼容入口只执行同源 replace，保留 query/fragment，且不等待身份接口恢复。旧 `#/question/:id?...#anchor` 先迁移再交接。通知中心使用 `/users/notifications/inbox` 的完整原生能力。

本地独立 Answer 验证了列表到详情、收藏写入后个人收藏可见、公开作者、旧通知跳转与编辑器草稿保护。测试不使用生产账号写入；未把所有原生上传/审核/邮件流程宣称为本轮逐项重测。

## 账号与管理入口

`/login`、`/register`、`/forgot`、`/publish` 直接交接到对应原生表单，保留参数、不等待身份读取；配置不能把这些交接变为外站或壳层循环。私人空间提供公开主页、资料编辑、退出登录，侧栏提供账号设置；仅正常激活的真实管理员显示社区管理、连接配置和 Pulse 配置。前端入口不是权限授予，服务端检查不变。

真实验收发现并修复原有问题：个人帖子字段为 `question_id`，不能只读取 `id`；Answer 1.7.1 的 UserCenter 注册守卫不尊重本地账号模式。插件仅在自己启用且 `enabled_original_user_system=true` 时将前端注册目标修正为 `/users/register`，不改注册开关、身份、角色、登录目标或任何后端校验。中英文 YAML 通过 `go:embed` 纳入 vendoring，确保 Answer 构建合并语言资源。

以上阶段为代码与本地交付状态。正式上线还需部署含插件的 forum 镜像和新版静态站点，并对生产登录、邮件、验证码、上传与管理权限做环境验收。
