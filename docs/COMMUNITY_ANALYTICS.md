# 社区经营看板与指标口径

入口：管理员头像菜单 → **社区经营**（`/admin/operations`）。Answer 正常、已验证的管理员可看总览和维护用户运营标签；每次服务端请求重新检查当前角色。普通成员不可读取运营标签或报表。数据只用于社区经营，不用于贡献、抽奖资格或财务记账。

## 建议怎么用

每周优先看 **有效周活人数、D7 有效留存、24 小时获回应率**：分别回答有多少人真正参与、是否愿意回来、发帖后是否得到帮助。配合新增注册、周发帖人数，判断增长来自新用户还是现有用户。先积累四周基线再设目标，避免给小样本拍固定达标线；看留存时同时看分子、分母，不能平均各日百分比。

每日看新增注册、昨日有效日活、待回答主题，及时处理内容缺口；每周看近 7 日去重发帖/回答人数、成熟注册队列留存与前七工作日活跃分布；每月看有效月活、注册转化耗时及标签分群。增长、内容和参与指标一起判断，避免只增加注册总量却没有持续交流。

## 第一版指标

| 指标 | 口径与用途 |
| --- | --- |
| 注册总数、可用数、已验证数 | Answer 账号事实；“已验证”是邮箱和账号状态，不是行为激活。注册总数包含封禁/删除账号的历史注册，避免从留存分母中删除流失用户。 |
| 新增注册 | 最近 7 个完整自然日；总览时间固定到昨日。 |
| 访问 DAU / WAU / MAU | 登录用户在 1/7/30 个完整自然日内发生前台访问、有效发帖或回答，按 Answer 用户 ID 跨日去重。 |
| 有效 DAU / WAU / MAU | 前台有焦点的帖子阅读累计 30 秒，或发布当前有效的帖子/回答。隐藏页、连续无交互超过 60 秒不累积阅读；只签到、抽奖或刷新不算有效活跃。 |
| 匿名访客 | 按浏览器随机 Cookie 日级去重，单独展示。不能与登录用户简单相加，也不是唯一自然人数。 |
| D1 / D7 / D30 有效留存 | 注册日 D0 后第 1/7/30 个自然日**当天**有效活跃人数 / 该日注册人数；仅完整观察并已到期的队列参与。不是“七天内回来过”。 |
| 前七法定工作日 | 从注册次日起取中国法定工作日，含调休。展示平均有效活跃天数、至少活跃一天的人数、样本人数和 0–7 天分布。只在七个工作日全部结束后给结果。 |
| 7 日访客注册转化率 | 选定范围中首次观察、已满 7 天的匿名浏览器，有多少在首次观察后 7 天内注册。已识别的老账号排除。 |
| 注册耗时中位数 / P75 | 同一浏览器首次观察到新账号注册的时间，仅统计 30 天内成功关联者。同时显示关联注册数 / 同期新增注册数；未注册者不进入耗时分位数。 |
| 周发帖人数 / 回答人数 | 最近 7 个完整自然日发布有效内容的去重用户数；多次发布只算一人。帖子/回答数量另列。 |
| 24 小时获回应率 | 最近已成熟的 7 个发布日（昨日之前）中的有效主题，在发布后 24 小时内获得他人有效回答的比例。自答不计；未回答主题留在分母。 |
| 首次回应中位耗时 | 同一发布队列中，已获他人有效回答主题的首次回应耗时；与回应率一起看，不能单看速度。 |
| 待回答主题 | 当前有效主题中尚无他人有效回答的数量。 |

统一使用 `Asia/Shanghai`。总览的日/周/月指标截至昨日，范围选择 7/30/90 天作用于每日趋势和注册队列；周供给指标固定 7 天。选 7 天时访客队列尚无完整 7 日观察窗口，转化率为无样本。内容有效性按当前 Answer 审核状态重算：主题状态正常/关闭，回答正常且所属主题有效；删除、待审核内容不计。

管理员和带精确运营标签“内部测试”的用户从经营用户、注册队列及内容供给统计中排除；排除随当前角色/标签重算。给真实用户的回复仍可由管理员提供，回应率不把管理员帮助视为无回应。匿名浏览阶段无法可靠识别管理员或内部测试者，不声称匿名流量完全排除了内部访问。

## 中国法定工作日日历

2026 年日历依据[国务院办公厅通知（国办发明电〔2025〕7号）](https://www.gov.cn/zhengce/content/202511/content_7047090.htm)，包括 1 月 4 日、2 月 14/28 日、5 月 9 日、9 月 20 日、10 月 10 日调休上班。注册当天不计入前七个工作日。

当前仅内置已经核验的 2026 年通知。跨入未覆盖年份时显示“日历待更新”，不能把普通周一到周五冒充法定工作日。后续年度通知公布后，更新 `analytics/calendar.go` 与相应假期/跨年回归，再发布；不影响自然日留存。

## 数据完整性与隐私

新版本部署后的首次成功采集初始化观察起点。第一个完整日是该时刻之后的上海午夜；此前的活跃、留存与完整观察不足的队列显示“—”或“未完整观察”，不是零、不补造历史。既有注册和帖子/回答可从 Answer 直接计算。

异步采集同时覆盖 METAR 壳和原生 Answer 内容页。尊重浏览器 Do Not Track / Global Privacy Control；已知爬虫 User-Agent 不记，无法保证排除全部机器人。拦截、离线、清理 Cookie、共享浏览器或跨设备会造成漏记或归因偏差；这是运营估计，不能用于奖励或计费。采集失败不阻断浏览、登录或发帖。

Cookie `metar_ops` 为随机 256 位标识，Secure + HttpOnly + SameSite=Lax，90 天有效，路径限 `/answer/api/v1/metar/analytics`；网关仅在该路径转发。数据库只存其 SHA-256、首次/最近观察时间、来源域名、可关联的新注册账号及日级去重活动，不保存 IP、完整 URL/查询参数、搜索词、正文、私聊或 API 凭据。不跨站或跨设备推断身份。浏览器上报不接受 user_id，登录主体只能来自 Answer 服务端会话。

新表归入现有 Answer MySQL 备份；当前不自动清理历史日级聚合与审计。查询只开放 7/30/90 天且有超时和数据行数上限，超限返回不可用，不静默截断报表。规模扩大时应增加可重建汇总与明确保留策略，不能让同步全库扫描持续增长。

## 用户运营标签

管理员可按用户名/昵称或精确标签筛选，每人最多 12 个标签，每个最多 32 字。建议从少量能触发行动的标签开始，例如“新用户待引导”“API 用户”“内容贡献者”“待回访”；不要给标签赋予未验证的敏感身份推断。标签不显示给普通成员，不改变 Answer 内容标签、权限、封禁或 Pulse 奖励。

每次保存携带版本号和幂等请求键，事务记录操作者、修改前后值与时间。版本冲突先刷新核对；响应丢失时重试同一请求，避免重复审计或覆盖他人的修改。审计目前保存在数据库，未提供独立审计列表界面。

## 后续按经营问题增加

- 新用户激活漏斗：注册 → 完成首次有效阅读 → 首次发帖/回答；定位引导环节，单独定义行为激活。
- 内容主题分布、浏览转回答、搜索无结果率：定位供需缺口，需要新的页面级事件与聚合，当前不假装已有数据。
- 来源渠道分群、标签分群留存和创作者留存：先保证样本量，再比较同成熟度队列。
- 举报量、处理时长、垃圾内容比例：作为质量护栏；不能只追发帖量。
- 元衡 API 绑定与真实付费调用转化：若要衡量商业转化，须经过现有受保护绑定与最小化数据接口；本版不访问 new-api 资金或调用链路。
