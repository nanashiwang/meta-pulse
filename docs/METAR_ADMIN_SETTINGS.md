# METAR 管理员配置

管理员登录社区后，可从用户菜单进入 **Pulse 配置**，地址为 `https://metar.uk/admin/pulse`。页面管理 Pulse 对接参数和运行开关；new-api 的到账上限仍在 new-api 后台配置，贡献倍率、产券门槛与奖池可通过本页「设置兑换比例」保存为长期生效规则。底层历史规则快照仍由审计工具保留，用户界面不再以周期方式管理；所有未用券统一使用最新奖项、概率和预算，原有效期保持不变。

## 首次启用

1. 使用正常 `metar update` 更新 API、Worker、论坛插件和社区前端，不使用 `--skip-worker` 或 `--skip-forum`。更新会应用 `00012_runtime_settings.sql`。
2. 在 Answer 后台 `/admin/pulse_user_center` 的 **Pulse 管理配置 HMAC 密钥**（`admin_hmac_secret`）填入现有 Pulse `.env` 中 `PULSE_ADMIN_HMAC_SECRET` 的值并保存。这是一次性的管理通道配对；不复用 SSO、Profile、社区用户 BFF 或发奖密钥。
3. 打开 `/admin/pulse`。首次没有网页覆盖值时沿用原部署配置，因此升级不会自动打开活动或更换已有业务密钥。

只有 Answer 本地管理员可以使用。普通用户、版主、封禁账号、未激活账号、已被撤销管理员权限的旧会话均不可读写；管理员不需要绑定 new-api。配对密钥缺失时只关闭管理页，不影响社区本地登录和浏览。

## 页面可配置内容

- API 额度换算：字段为“每 1 ⚡️ 对应 quota”，填写与 new-api `QuotaPerUnit` 一致的正整数。⚡️ 仅统一额度标识，不改变奖项的实际 quota 数量。
- 新抽奖开关及影子模式；打开新抽奖不等于 new-api 已允许到账，接收端仍有独立开关和限额。
- Profile、new-api 用户 BFF、社区 BFF、运营、发奖、撤销的当前/上一组 HMAC 密钥。每种用途独立；页面注明需要同步到 new-api 或插件的对应字段。
- new-api 私网目标地址：Worker 登记结算身份前可配置；一旦登记或存在奖励记录便锁定，以免不确定的旧奖励被送往另一个资金系统再次发放。Worker 首次登记会将目标固化到数据库，随后修改 `.env` 不会迁移该目标。迁址需要维护窗口和专门的数据/在途奖励迁移方案，本页面不提供解锁按钮。

运行环境、数据库/Redis 连接、LOG_DB 只读凭据、随机种子和活动经济规则不在该页面编辑。社区 SSO、邮件与绑定继续使用 Answer 原生后台，页面提供入口。

## 密钥与保存

新配置页只显示密钥是否已配置、来自部署环境还是数据库，不回显已有密钥。空白输入保留原值；删除旧密钥须明确勾选清除。生成按钮只生成当前用途的新值，不自动保存，也不会同步修改另一端。首次配置时两端填写同一用途的相同值；轮换时，先在验签接收端一次保存“新当前密钥 + 原当前密钥作为旧密钥”，再切换发送端，待在途请求结束后清除旧密钥。当前和旧密钥必须不同，不能先单独保存一份仍等于当前值的旧密钥。浏览器不把密钥、草稿或待重试请求写入 localStorage/sessionStorage。

运营侧密钥用于当前配置页自身的鉴权：先在本页同时保存新 `PULSE_ADMIN_HMAC_SECRET` 与原值作为 `PULSE_ADMIN_HMAC_SECRET_PREVIOUS`，成功后再更新插件 `admin_hmac_secret` 和 new-api 的运营侧密钥。不要先改插件，否则新签名尚未被 Pulse 接受，配置页会暂时无法使用。

Answer 原生插件配对页遵循 Answer 自身的 password 配置协议；不要把新页面的只写不回显保证理解为原生插件配置接口也不向授权管理员返回字段值。

每次保存需要操作原因。API 以服务端认证身份记审计，并通过配置版本和幂等键拒绝并发覆盖；同一请求重试返回首次结果。网络结果不确定时使用页面的原请求重试，不能重新生成另一份保存操作。明确版本冲突时保留输入，重新读取最新配置后人工核对。关闭/离开页面会清除内存中的秘密草稿；刷新后先查看当前配置状态，不盲目补写。

保存成功后，API 新请求读取新快照；Worker 在下一轮结算、对账、关期任务开始时读取（默认间隔 30 秒），在途任务继续使用原快照。配置读取或解密失败时拒绝业务操作，不偷偷回退到旧密钥或旧开关。页面的“发奖密钥存储已就绪”仅表示 Worker 加密接收身份已登记，不代表 Worker 在线或已经实际到账。

网页保存的覆盖值优先于 `.env`。保留原 `.env` 作为初始部署基线；登记后擅自改变角色的环境密钥会被拒绝，避免不同副本使用不同凭据。后续业务密钥轮换通过页面与对端同步完成。

## 加密与备份

API 和 Worker 在各自专用持久卷首次生成配置加密私钥，不会轮换业务 HMAC 或奖励随机种子：

| 角色 | Compose 卷 | 容器内路径 |
|---|---|---|
| API | `pulse_api_runtime_keys` | `/app/runtime-keys/api.key` |
| Worker | `pulse_worker_runtime_keys` | `/app/runtime-keys/worker.key` |

数据库保存分角色密文。API 可以用 Worker 公钥封装管理员提交的发奖密钥，但无法解密已保存的 Worker 密钥，也不创建发奖客户端；Worker 只能解密发奖密钥，不持有 API、BFF 或撤销私钥。私钥丢失或密文损坏时必须恢复原卷，不能通过新建空卷绕过错误。

更新脚本会把已有卷中的私钥备份至本次 `.data/deploy-backups/.../runtime-keys/{api,worker}/`，与数据库 dump、原 `.env` 一起保护和恢复；复制失败会停止更新。首次从旧版本升级时尚无私钥卷，后续应另做一次完整备份。备份包含敏感凭据，禁止提交 Git、上传公开附件或只备数据库而丢弃私钥。多副本部署必须给同一角色共享相同私钥及环境基线，API/Worker 两个角色之间禁止共享私钥卷。

`reconcile`、`reward-retry`、`period-close` 等财务工具需在 `pulse-worker` 容器内执行，以读取同一私钥及后台配置，例如 `docker compose exec -T pulse-worker meta-pulse-tool reconcile`。迁移、只读检查、周期创建不需要这些加密私钥。

## 配置贡献倍率与脉冲券比例

首次创建默认勾选 **不限制额度奖励总量**；已有规则保留原有限/不限模式，有限预算留空，必须重新核对填写，避免自动补满历史总额。不限模式无需配置额度预算；按需要配置额度奖项和概率权重。取消勾选可恢复有限额度预算。**预览概率与期望** 按实际表单列出有效券、到期券概率以及 API/EXP 平均奖励，例如 10% 出 100 quota、90% 出经验，则期望为每次 10 quota。期望不保证实际累计支出，经验预算仍单独限制。所有未用券的新抽奖统一采用最新预算模式；历史已中奖奖励继续在原预算结算。

在 `/admin/pulse` 点击 **设置兑换比例**，填写额度奖励有效天数（默认 30 天）、API 贡献倍率和每张脉冲券所需贡献度，无需设置周期编号或开始日期。例如倍率 `1.25`、门槛 `1000` 表示按 1.25 倍计算有效付费贡献，每累计 1000 贡献度产生一张券。贡献倍率最多 4 位小数，门槛最多 3 位小数；前端精确转换为整数 bps / milli。

同时填写额度预算（new-api 整数 quota）、经验预算（整数 EXP）、各奖项数量与权重，至少保留一个经验奖项。概率等于奖项权重除以总权重，每次独立抽取，中奖不会降低后续概率。券从获得时起计时，满有效天数后仅在最新经验奖项中按权重抽取；前台显示当前券余额与额度资格，概率由管理员预览，已有券原截止时间保留，新有效天数只适用于后续获得的券。

填写原因并核对新预算，点击 **保存统一规则**。保存创建长期生效的不可变规则快照：新奖项、概率与预算适用于所有未用券；贡献倍率与产券门槛只影响后续贡献转换，已有券数量与原有效期不变，未成券贡献继续累计。新抽奖只消耗最新规则预算，不合并历史余额；已中奖奖励仍由原预算预留、结算和撤销。任一适用预算不足时暂停对应抽取，不扣券、不降低概率、不回退旧规则。保存不会自动打开抽奖或发奖开关。

管理员身份由 Answer 实时复核后签名传入 Pulse，普通用户不能保存规则。创建与幂等结果、经济规则、奖池、预算、审计在同一事务完成。网络失败时点击 **重试原请求**；待确认请求（不含密钥）暂存在当前标签页 sessionStorage，刷新后仍使用同一请求编号与内容，成功后清除。若配置已被其他管理员更新，刷新列表后核对，不能覆盖已启用规则。只有后端声明支持持续规则时才显示编辑器；旧版本提示升级，其余配置继续可用。

### 50% 额度概率方案（v0.2.39）

点击 **载入 50% 额度概率方案** 可填入下表。按钮仅替换奖项与修改原因，不重置门槛、倍率、有效期、有限/不限模式或预算输入，也不发送保存请求。已有规则打开时仍显示原奖项，升级代码不会自动改变线上奖池。

| 类型 | 数量 | 权重 | 有效券概率 | 到期券概率 |
|---|---:|---:|---:|---:|
| API | 0.25 ⚡️ | 44000 | 44% | — |
| API | 1 ⚡️ | 5000 | 5% | — |
| API | 5 ⚡️ | 800 | 0.8% | — |
| API | 25 ⚡️ | 200 | 0.2% | — |
| EXP | 1 | 28000 | 28% | 56% |
| EXP | 4 | 12000 | 12% | 24% |
| EXP | 20 | 10000 | 10% | 20% |

总权重 100000。有效券 API 概率 50%，期望 0.25 ⚡️；EXP 期望 2.76。到期券原额度截止时间不变，只抽 EXP，期望 5.52。五张均有额度资格且实际完成五次独立抽奖时，至少一次 API 奖励的概率为 96.875%，没有保底。

等期望比较基准为用户确认的旧奖池：1.25/2.5/10/50 ⚡️，权重 8000/2000/500/100，API 期望同为 0.25 ⚡️；不是仓库旧预设的 0.05 ⚡️。金额按当前 `quota_per_unit` 精确生成，不能改换算比例来凑奖项；例如单位 100000 时，四档整数 quota 为 25000/100000/500000/2500000。经验不进行 quota 换算。换算比例须为 4 的倍数，最大单奖不能超出安全整数范围。

`预览概率与期望` 始终读取当前表单，修改奖项后旧预览清空。用户 `/pulse` 不展示奖池概率，奖励记录通过默认收起的入口查看；规则接口仍提供执行所需的签名选择。百分比为展示值，非有限小数标记近似，实际抽取仍使用原始整数权重。

保持单券期望不等于固定周支出，新增每日券或提高使用率都会改变实际抽奖量。若维持本期总预算（例如每周 10000 ⚡️），须先暂停新抽奖、核对在途及旧奖励的已发放/预留，再将剩余授权额度配置给新规则，不能复制一整份旧预算或把历史余额相加。当前预算查询是快照，系统不自动转移、锁定或重置周预算。本预设不修改发券门槛、不新增每日券、不打开抽奖/发奖开关。

### 当前规则与历史预算核对

v0.2.38 起，用户无需选择历史规则或发放批次。到期券保持原期限，使用最新经验奖项；五连抽可以跨批次，但每次操作固定确认的规则、目标券及资格。预览不预留券，管理员改规则或目标状态变化时需要重新确认；已提交请求恢复原结果。

「各规则预算」列出最近 20 个规则的预算编号、总额、预留、结算和可用额。新抽奖只使用当前规则预算，历史预算保留已中奖奖励的责任，不与新余额相加。API 使用原始整数 quota，经验使用 EXP。不限额度总量不保证固定周支出，接收端限额仍生效。
