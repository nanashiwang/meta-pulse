# Answer 本地首字母头像

`avatar-head.html` 是 Answer 1.7.1 官方「外观 → 自定义 → 头部」扩展片段，不修改 Answer 源码或用户头像记录。默认头像、被阻止的头像和加载失败的头像显示用户名首字符；本地上传成功的图片正常显示。昵称只在页面缺少用户名时兜底。导航通过 Answer 自己的同源只读用户接口取得用户名，沿用当前 Answer 会话，不复制会话、不联系外部头像服务。

## 应用与更新

1. 在 Answer 后台「站点设置 → 界面」将默认头像设为「System」，保存。这样新用户默认不会先尝试访问 Gravatar。
2. 备份「外观 → 自定义」原有内容，将 `avatar-head.html` 的完整内容追加到「头部」并保存。更新片段时替换原来的 `metar-local-avatars` 区块，不重复追加，也不覆盖其他定制。
3. 刷新个人页、问题列表及导航，确认首字母正常显示。

该配置保存在 Answer 数据库中，容器更新、重建后保留。`metar update` 更新仓库内片段但不会覆盖站点外观配置；片段本身有新改动时需在上述入口更新。回退时移除该区块并刷新；需要时恢复原默认头像设置。

用户在「编辑资料 → 头像 → 自定义」上传图片后保存。上传、文件校验、资料更新与权限仍由 Answer 负责；不要把用户头像同步写成 new-api/Pulse 资料。外域自定义头像继续遵守 Answer 外部媒体保护，脚本不放行帖子中的外部图片。

## 验证

`make test-community` 包含首字符、SVG 转义、同源用户名解析及默认头像识别回归。浏览器验证需覆盖：被移入 `data-src` 的 Gravatar、普通默认图、成功上传图、失败图、SPA 新头像、上传替换旧回退，以及帖子图片不受影响。

升级 Answer 时还需核对 `Avatar` 元素的宽高/圆角 class、`/users/{username}` 资料链接、设置页 `input#username` 和导航 `#dropdown-basic` 是否改变。
